# Gemini API CLI 연결

Gemini로 얼굴·유니폼 참조를 합성하는 선택 기능입니다. 기본 생성 방식은 기존 ChatGPT · Codex로 유지합니다.
연결 대상은 코딩 에이전트 `gemini`가 아니라 Google의 실험적 이미지 생성 도구 **`gemini-api`**입니다.
Windows EXE는 별도로 준비하며 앱이 내려받거나 설치하지 않습니다.

## 준비와 연결

1. [공식 배포 페이지](https://github.com/google-gemini/gemini-api-cli/releases)에서
   Windows x64용 `gemini-api_Windows_x86_64.zip`을 받아 쓰기 가능한 전용 도구 폴더에 풉니다.
   이번 연결은 공식 **v0.5.0**의 명령·응답 형식으로 확인했습니다.
2. [Google AI Studio](https://aistudio.google.com/)에서 Gemini API 키와 유료 API 사용을 설정합니다.
   Google AI Pro·Ultra의 월별 API 크레딧을 쓰려면 주 구독자 계정에서 크레딧 수령과
   Cloud Billing 연결을 완료해야 합니다. 구독 로그인만으로 API 연결이 완료되지는 않습니다.
   선불 계정의 초기 충전·잔액 조건과 초과 요금은
   [Google 공식 안내](https://ai.google.dev/gemini-api/docs/google-ai-plans)를 확인하세요.
3. 앱의 **폴더 · 연결 → 이미지 생성 방식 → Gemini · API CLI**를 선택합니다.
4. **Gemini API CLI → 선택**에서 압축을 푼 `gemini-api.exe`를 지정합니다.
   `gemini.exe`, npm의 `.cmd`/`.bat` 실행기는 사용할 수 없습니다.
5. **Gemini API 설정**을 누릅니다. CLI의 `configure --interactive` 창에서 API 키를 설정합니다.
   CLI가 인증 정보를 자체 관리하며 앱의 `config.json`·프롬프트·진단 보고서에 키 입력란/키 사본을 만들지 않습니다.
   이미 CLI 또는 환경 변수로 인증을 설정했다면 다시 입력하지 않아도 됩니다.
6. 이미지 모델은 기본 `gemini-nano-banana-2.1`을 사용하거나 본인의 API에서 제공되는 호환 모델을 입력하고
   **설정 저장**을 누릅니다. 1K 정사각 PNG 출력을 지원하는 이미지 모델이 필요합니다.

**‘Gemini API CLI 확인됨’은 설치 확인일 뿐입니다.** 유효한 키·결제·모델 권한은 실제 요청에서 확인합니다.
인증 확인을 위해 앱이 유료 테스트 이미지를 자동 생성하지 않습니다.

## 한 명으로 테스트

1. 기존 페이스팩과 **2026/27** 키트 폴더를 연결합니다.
   얼굴은 직접 생성의 참조 사진으로 넣을 수도 있고, 키트는 작업 메뉴의 유니폼 변경으로 지정할 수도 있습니다.
   골키퍼에는 골키퍼 참조가 필요합니다. 로컬 키트의 실제 시즌을 앱이 자동 판별하지는 않습니다.
2. **직접 생성**에서 선수·유니폼 구단·원하는 개별 지시를 지정해 요청합니다.
3. 대기열에서 실행한 뒤 얼굴·자세·구도 유지와 유니폼 재현을 확인합니다.
   최종 파일은 기존과 같이 선수 ID 이름의 350×350 PNG이고 이름·모서리는 로컬에서 렌더링합니다.
   성공할 때마다 config.xml을 갱신하고 기존 게임 새로고침 설정도 따릅니다.
4. 실제 사용량은 AI Studio의 사용량/결제 화면에서 확인합니다. 앱의 일일 한도는 작업 수 기준입니다.

## 현재 범위와 주의점

- **Gemini 경로는 얼굴·키트 참조가 모두 있는 작업부터 지원합니다.** 누락된 참조의 웹 검색·다운로드는
  Gemini 이미지 CLI에 맡기지 않고 AI 호출 전에 보류합니다. 참조를 지정하거나 기존 Codex 방식을 선택하세요.
  Codex로 몰래 전환하거나 다른 API로 대체 호출하지 않습니다.
- 얼굴과 키트 두 장, 26/27 시즌·골키퍼 구분, 공통·개별 지시를 전달합니다.
  충돌 시 개별 지시를 우선하며 출력 크기·이름·프레임은 앱이 처리합니다.
- 게임/사용자가 제공한 영문 이름이 없으면 Gemini 텍스트 모델로 이름의 라틴 표기를 먼저 확인합니다.
  이때 **이미지 호출 외에 텍스트 API 요청 한 번**이 추가됩니다. 이름 확인에 실패하면 이미지 요청을 하지 않습니다.
  텍스트 모델의 기본값은 `gemini-4-hydrogen`이며 필요한 경우 config.json의 `gemini_text_model`로 변경할 수 있습니다.
- 현재 작업 중단은 CLI 프로세스와 자동 생성을 중단합니다. 이미 서버에 제출한 요청의 과금을 취소한다고 보장하지 않습니다.
  로컬에 완전한 합성 PNG가 남은 경우 복구 기록을 만들어 재시도 시 추가 이미지 요청 없이 재사용합니다.
- 결과 PNG/XML 저장 실패도 기존의 합성 원본 재사용 경로를 사용합니다. 설정·기록·다른 팩 매핑을 초기화하지 않습니다.
- 실패한 작업의 `events.jsonl`, `stderr.log`, `reply.json`으로 확인합니다. 없는 파일은 제외합니다.
  인증 설정 창의 내용과 CLI의 별도 인증 파일은 공유하지 마세요.

## 검증 범위

- 모의 API 결과로 합성→영문 이름→350×350 PNG/XML 저장, 개별 지시, 중단·저장 실패 복구를 검증했습니다.
- SHA-256 확인 후 받은 공식 Linux v0.5.0 실행 파일로 두 참조의 image 명령과 generate 명령을 dry-run했습니다.
- 같은 실제 CLI를 로컬 모의 HTTP 서버에 연결해 이름 JSON 파싱과 이미지 파일 저장을 확인했습니다.
  Google API나 유료 모델을 호출한 테스트가 아닙니다.
- Tk 화면에서 생성 방식 전환·설정 저장을 확인했습니다. 실제 Windows API 설정 창·개인 계정 권한·실제 합성 품질은
  사용자 PC에서 위 한 명 테스트로 확인해야 합니다. 새로고침 DLL은 수정하지 않았습니다.
- 전체 Python 테스트 **467개 통과(GUI 포함, 41.715초)**. 설정 창 1180×740에서 항목이 화면 밖으로 나가지 않음을 확인했습니다.
  Windows 설치 EXE는 이 Linux 환경에서 빌드하지 않았습니다. 소스 실행 사용자는 소스를 업데이트하고,
  설치형 사용자는 Windows에서 새로 빌드한 Setup으로 기존 설치 위치를 업데이트해야 합니다.
