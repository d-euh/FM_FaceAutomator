# 세이브 팀 구분과 실제 게임 참조 대조

세이브의 팀 유형 값이 실제 게임의 리저브·유소년 참조와 어떻게 연결되는지
확인하는 일회성 조사 도구입니다. 앱의 분류 방식을 변경하는 업데이트는 아닙니다.

## 실행

1. 저장소 **소스 폴더**에서 `git pull`로 업데이트합니다.
2. 앱의 자동 생성을 멈추고, FM27에서 이전에 제공한 팀 검증 세이브 중 하나를
   불러옵니다. 도구가 끝날 때까지 시간 진행·저장·다른 세이브 불러오기를 멈춥니다.
3. 소스 폴더의 `verify_save_team_roles.bat`를 실행하고 **지금 게임에 불러온
   동일한 `.fm` 파일**을 선택합니다. 기존 팀 조회 DLL이 정상 연결돼 있어야 합니다.
   연결 대기 표시가 뜨면 도구를 닫지 말고 FM27 창으로 전환해 응답 상태를 확인합니다.
4. 완료되면 소스 폴더의 `diagnostics/save-team-roles.json`을 대화에 첨부합니다.
   오류가 기록됐어도 생성된 JSON을 첨부하면 됩니다.

기존 `.venv`가 없다는 메시지가 나오면 먼저 소스 폴더의 `setup_windows.bat`를
실행합니다. 설치 EXE의 폴더가 아닌 저장소 소스 폴더에서 사용하는 조사 도구입니다.
새 DLL 설치나 게임 API 변경은 필요하지 않습니다.

## 검증 범위

제공된 세이브에서는 관찰된 유형·플래그·별도 구단 연결 조합을 대표하는
25개 구단, 79개 팀이 선택됩니다. 다른 세이브의 표본 수는 달라질 수 있으며
256개 팀을 넘는 표본은 조회하지 않습니다. 대표 표본은 전 세계 구단의 검증을
완료했다는 뜻이 아닙니다. 담당 구단과 이전 검증 구단인 맨유·바르셀로나를 먼저
조회하므로 핵심 비교 자료가 초기에 수집됩니다.

도구는 세이브 복사본을 읽고 기존 `TeamReader`의 요청·세션·담당 구단 확인·
정리 절차를 재사용합니다. 각 팀의 고유 ID와 저장 구단 ID를 확인하고, 부모
구단 기준 팀에서 반환한 실제 `ReservesTeam`·유소년 참조를 함께 기록합니다.
B팀 자체의 `IsFirstTeam=True`와 부모 구단에서의 역할을 구분해 비교합니다.

게임 서비스가 실제로 불러온 파일명·파일 해시를 제공하지 않으므로, 선택한
세이브와 불러온 세이브가 같은 파일인지는 사용자가 맞춰야 합니다. 이 제한은
보고서의 `loaded_save_file_verified: false`에도 명시됩니다. 일시적인 게임 진행·
연결 지연에는 120초의 재시도 예산을 두고 기다립니다. 진행 중인 개별 요청의 대기·
정리 시간은 별도입니다. 같은 세션·조회 시점·세이브의 결과만 재사용하며,
조회 문맥이 바뀌면 기존 연결 검증에 따라 다시 확인합니다. 시간 초과나 정리 오류
등에는 중단하고 오류·미검증 응답을 기록하며, 자동 분류 규칙을 적용하지 않습니다.

AI 호출·페이스온 저장·그래픽 갱신은 실행하지 않습니다. 원본 세이브·선수 배정·
설정·페이스팩은 수정하지 않습니다. 보고서에는 선택한 세이브의 파일명·해시·날짜,
표본 구단과 팀의 ID·유형·참조·조회 문맥이 들어가며, 세이브 원본·사진·인증 정보는
들어가지 않습니다.
