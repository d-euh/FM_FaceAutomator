# FM Face Refresh · 0.2.0 실험 기능

FM Face Automator **v0.10.0**의 선택 기능입니다. 사용자에게서 받은 진단으로 확인한 **Windows x64 · Steam 26620374 · BepInEx 6 IL2CPP be.793**을 대상으로 합니다. 빌드 ID뿐 아니라 `fm.exe`, `GameAssembly.dll`, `fm_Data/Plugins/x86_64/game_plugin.dll`의 SHA-256이 진단과 일치해야 로드합니다. 다른 게임 업데이트나 파일 변경은 거부합니다.

**DLL 빌드와 자동 테스트는 통과했지만, 이 플러그인의 실제 FM27 화면 반영은 아직 검증하지 않았습니다.** 메타데이터 진단 플러그인이 해당 PC에서 정상 로드된 것과 이 갱신 플러그인이 실제로 작동하는 것은 별개의 확인입니다. 첫 테스트 전에는 완성된 자동 적용 기능으로 보지 마세요. 설정 기본값은 꺼짐입니다.

## 설치와 첫 테스트

1. FM27과 앱을 종료하고 저장소를 업데이트합니다.

   ```powershell
   cd D:\FMFaceAutomator
   git pull --ff-only
   .\install_live_refresh.bat
   ```

2. 기존 진단 때 설치한 BepInEx be.793을 그대로 사용합니다. 설치 도구는 `BepInEx\plugins\FMFaceRefresh\FMFaceRefresh.dll`만 설치합니다. 이미 같은 플러그인이 있으면 이전 DLL을 `.dll.previous`로 보관하며 다른 모드와 로더는 교체하지 않습니다. 처음 플러그인을 읽기 위해 이번에는 게임을 시작해야 합니다.
3. FM27에서 세이브를 불러오고 날짜 진행·경기·저장을 멈춘 평상시 화면에서 대기합니다.
4. 앱을 실행합니다. **폴더 · 연결** 아래의 **생성 후 게임 그래픽 갱신 · 실험 기능**을 체크하고 **설정 저장**을 누릅니다.
5. 이미 생성했지만 게임에 아직 반영하지 않은 선수 사진으로 **게임 갱신 테스트 · AI 호출 없음**을 실행합니다. 이 버튼은 새 이미지를 생성하지 않습니다.
6. 같은 화면 하단의 상태와 게임의 얼굴 표시를 확인합니다. **게임 그래픽 갱신 처리 완료**는 게임의 완료 콜백과 화면 갱신 호출을 확인했다는 뜻이며, 얼굴 이미지의 정확성까지 자동 판정한 것은 아닙니다.

첫 테스트가 성공하면 이후 자동 생성으로 PNG·config.xml을 저장할 때 같은 갱신을 요청합니다. 연결이 없으면 요청할 내용을 작업 기록에 보관하며, 게임 갱신이 실패해도 PNG·XML의 **생성 완료** 상태를 실패로 바꾸거나 AI를 재호출하지 않습니다. 끄면 이후 갱신 요청을 보내지 않으며 이미 게임에서 시작한 갱신은 마칠 수 있습니다.

## 대기하거나 실패할 때

```powershell
.\export_live_refresh_report.bat
```

열린 폴더의 **live-refresh-report.json**을 대화에 첨부하세요. 게임·세이브 파일은 필요 없습니다. 상태에는 최근 요청 결과, 게임 상태 이름과 열거형 목록, 등록 경로의 속성 이름이 포함됩니다. 플러그인은 네트워크로 보고서를 전송하지 않습니다.

| 상태/이유 | 동작 |
| --- | --- |
| 게임 로딩·진행·경기 또는 알 수 없는 상태 | 실행하지 않고 대기합니다. 알 수 없는 상태 이름을 정상 상태로 추측하지 않습니다. |
| `unrecognized_or_busy_game_state` | 게임 상태 이름이 허용 목록과 다릅니다. 진단 보고서로 실제 이름을 확인해야 합니다. |
| `pack_not_under_registered_graphics_path` | 게임이 등록한 그래픽 경로 안에서 저장 폴더를 확인하지 못했습니다. 임의로 새 경로를 등록하지 않습니다. |
| 스캔 완료 콜백/화면 갱신 실패·시간 초과 | 자동으로 같은 호출을 반복하지 않습니다. 스캔 결과가 불확실하면 해당 세션의 갱신을 중단하고 게임 재시작이 필요합니다. |
| 빌드·파일 해시 불일치 | 게임 함수를 호출하거나 진행 방지 후킹을 설치하지 않습니다. |

전체 등록 그래픽 경로를 재검색하므로 큰 팩에서는 처리 시간이 걸릴 수 있습니다. 대기는 180초, 시작한 스캔은 60초까지 기다립니다. 종료·세이브 전환·타임아웃 후 늦게 도착한 콜백을 새 작업의 성공으로 쓰지 않습니다. 여러 FM27 프로세스가 연결되면 앱은 하나를 임의로 고르지 않습니다.

원래 진단만 수행하는 `FMFaceRefreshDiagnostics` 플러그인은 그대로 있어도 됩니다. 이 실험 기능을 제거하려면 FM27을 종료하고 `BepInEx\plugins\FMFaceRefresh` 폴더만 삭제합니다.

## 구현과 검증 범위

- 업로드한 메타데이터에서 확인한 `SI.Core.ResourcesSubsystem.RescanLocalPaths(Il2CppSystem.Action)` → 실제 완료 콜백 → `ClearCache()` → `SI.Bindable.PanelManager.ReloadPanels()` 경로를 사용합니다. FM26의 함수 주소나 메모리 배치는 복사하지 않습니다.
- 생성된 interop 래퍼에서 정확한 메서드 시그니처를 찾아 호출합니다. 게임 호출은 `TickSubsystem.Update` 뒤의 게임 스레드에서만 수행합니다.
- 활성 게임/매니저 하나, 로딩·처리 상태, 게임 상태 이름, 그래픽 초기화와 진행 중 스캔을 확인하고 2초간 안정적으로 대기해야 시작합니다. 스캔 중에는 확인한 Continue 진입점과 자동 카운트다운을 잠시 막으며, 완료·실패 후 방지를 해제합니다. 매치 엔진이나 세이브 내용을 수정하는 기능은 없습니다.
- 로컬 사용자 폴더 `%LOCALAPPDATA%\FMFaceAutomator\live-refresh`의 파일로만 통신합니다. 요청은 게임 세션 nonce, 고유 ID, 만료 시간, config.xml 해시와 연결됩니다. 다른 세션 요청이나 이전 결과를 재사용하지 않습니다.
- 요청 전송과 처리 완료를 구분합니다. 콜백이 오기 전에 완료로 응답하지 않고, 중복·늦은 콜백, 응답 유실, 스캔 중 새 결과, UI와 작업자의 동시 요청을 따로 처리합니다. 실패한 AI 요청의 재시도 정책은 바꾸지 않습니다.
- 자동 테스트에서 앱의 저장 성공 보존·추가 AI 호출 방지·요청 응답 검증, 상태기의 대기·완료·시간 초과·스캔 중 새 결과를 검증했습니다. 실제 게임 어셈블리를 가진 Windows에서의 호출과 시각적 반영은 사용자 테스트가 필요합니다. Linux 화면에서는 설정 기본값·저장·AI 없는 테스트 버튼을 확인했습니다.

개발자 빌드:

```powershell
dotnet build plugin-src/FMFaceRefresh/FMFaceRefresh.csproj -c Release -p:BepInExCoreDir="C:\FM27\BepInEx\core"
dotnet run --project plugin-src/FMFaceRefresh.Tests -c Release
python -m unittest discover -s tests -v
```

사용자는 .NET SDK를 설치하거나 직접 빌드할 필요가 없습니다. 포함한 DLL은 기존 진단 DLL과 같은 BepInEx 6 API 참조로 빌드했으며, 로더·게임 DLL을 함께 배포하지 않습니다.
