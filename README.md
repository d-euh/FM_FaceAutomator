# FM Face Automator

FM27 세이브 저장 후 이적을 감지하여 Codex CLI로 페이스온 합성을 요청하는 독립형 Windows 데스크톱 프로그램의 **미리보기 버전(v0.10.0)**입니다.

v0.10.0은 **Steam 26620374용 실험적 게임 그래픽 갱신 플러그인**을 추가합니다. `install_live_refresh.bat`로 설치 후 **폴더 · 연결 → 생성 후 게임 그래픽 갱신**을 켜면 파일 저장 성공 뒤 게임 갱신을 요청합니다. 기본값은 꺼짐이며, **게임 갱신 테스트 · AI 호출 없음**으로 먼저 확인할 수 있습니다. DLL 빌드·자동 테스트·앱 화면을 확인했지만 **실제 FM27 반영은 아직 미검증**입니다. [설치·테스트·실패 진단 안내](plugin-src/FMFaceRefresh/README.md)를 확인하세요.

v0.9.1은 완료된 작업의 설명을 **생성 완료**로 통일하고, 폴더 연결의 세이브 항목을 **연결할 세이브 파일**로 변경합니다. 전체 배경과 보라색 포인트를 한 톤 낮추며 버튼의 흰 글자는 유지합니다.

v0.9.0은 세이브별 작업 기록을 자동 관리하여 작업 폴더 입력을 제거합니다. 기존 기록은 연결해 유지하고 과거 시점으로 돌아가면 새 기준을 자동으로 만듭니다. 중복 홈·범위 이동 버튼을 제거하고 대기열은 자주 쓰는 조작과 **관리 도구**로 정리했습니다. **지정 선수 ID**로 명칭을 바꾸고, **커스텀 지시**에서 대기 작업을 이름으로 선택해 자동 생성 중에도 개별 지시를 저장할 수 있습니다. 골키퍼는 세이브의 포지션과 명시적인 골키퍼 키트 자료를 사용합니다.

v0.8.0은 홈에서 **최근 생성한 페이스온 최대 5개**를 **이전·다음**으로 넘겨 볼 수 있습니다. 최신 사진부터 표시하며 재시작해도 작업 기록에서 불러옵니다. 탭 이름은 **커스텀 지시**로 변경했고 기본 사진 스타일·추가 폼 템플릿 입력을 제거했습니다. 예전 설정에 남은 스타일·템플릿도 기본값으로 정리합니다.

v0.7.1은 사용자가 제공한 **Koverwatch · Bebas Neue · Venus Rising** 원본 폰트를 `fonts/`에 모두 포함합니다. **기본값은 koverwatch.ttf**이며 별도 설치·복사 없이 사용할 수 있습니다. **폴더 · 연결 → 이름 글꼴**의 드롭다운에서 세 폰트 중 선택하고 **설정 저장**을 누르세요. **기본 글꼴** 버튼으로 Koverwatch로 돌아갈 수 있으며 다른 TTF·OTF·TTC 파일도 직접 선택할 수 있습니다. 새로 생성하는 350×350 이미지의 **코너 반경 60px**은 유지합니다. 폰트 변경은 앞으로 생성하는 결과부터 반영하며 기존 결과는 자동 변경하지 않습니다.

추가 조건·호출량은 **고급설정 팝업**으로 분리합니다. 생성 범위의 **범위 저장 아래 왼쪽** 버튼을 눌러야 열리며 상단 탭에는 나타나지 않습니다. 닫기·X·Esc로 닫고 버튼으로 다시 열 수 있습니다. 기본값은 나이 전체·호출/재생성 제한 없음·생성 대기 없음입니다. 감시 간격은 **세이브 업데이트 횟수**로 정하며 기본 **1회(매 업데이트)**입니다. 2회 이상이면 각 저장의 이적을 기록하고 지정 횟수마다 누적 작업을 처리합니다. 최초 기준 읽기는 횟수에서 제외합니다.

앱 배경은 실버그레이 `#C8C9CF`, 본문은 짙은 회색, 카드는 밝은 회색입니다. 모든 동작 버튼은 차분한 보라 `#633078` 배경과 흰 글자입니다. 선택된 탭·강조 숫자에도 보라를 사용하며, 선택한 프리셋은 체크 표시로 구분합니다.

- 별도 생성 범위 탭: 내 구단·모든 이적·5대 리그·개별 리그·프리미어리그 빅6 원클릭 설정
- 구단 검색·추가 및 구단마다 영입만 / 방출만 / 모두 설정
- 홈에서 최근 생성 페이스온 5개 탐색·대기/생성/완료 수 확인
- 시작 시 세이브·기존 페이스팩·2D 키트·Codex 경로를 기본값에 자동 입력, 직접 수정 가능
- 중복 유니폼은 무작위 선택하여 자동 진행, 원하는 경우 수동 고정 가능
- 전체 공통 지시·작업별 개별 지시와 영문 표시 이름 설정
- 세이브별 작업 기록 자동 분리·이전 시점 저장의 자동 기준 분리
- 골키퍼 포지션 자동 판별·골키퍼 키트 선택
- `선수ID.png`, 350×350 건조형 PNG, 하단 영문 이름, 작업별 `config.xml` 자동 갱신
- 기존 파일이 있는 페이스팩에 직접 저장, 다른 이미지·매핑 보존, 대상 선수만 백업·갱신·복구
- 중복 이적 처리, 이전 상태의 결과 적용 방지, 백업·복구
- 등록 팀과 현재 계약 구단의 변경을 비교하고, 소속 변화·생성 범위 제외 사유를 진단 로그에 표시

## Windows에서 실행

Steam 빌드 **26620374**의 재시작 없는 적용을 조사하기 위한 **진단 전용 BepInEx 플러그인**과 설치·내보내기 배치를 추가했습니다. 아직 실시간 적용 기능은 아닙니다. 게임을 끄고 `install_refresh_diagnostics.bat` 실행 → FM27 시작 → `export_refresh_diagnostics.bat` 실행 순서입니다. BepInEx 6 IL2CPP x64 be.793 이상이 필요하며, [진단 사용 안내](plugin-src/README.md)를 먼저 확인하세요.

1. 이 저장소를 `D:\FMFaceAutomator`에 내려받습니다.
2. Python 3.12 이상(Tk 및 Python Launcher 포함)을 준비합니다.
3. `setup_windows.bat`를 실행한 뒤 `start_windows.bat`를 실행합니다.
4. Codex CLI를 설치·로그인합니다. 앱에서 자동 입력한 경로를 확인하고 필요한 항목만 바꿉니다.
5. **생성 범위** 탭에서 범위를 정하고 **범위 저장** 후 홈이나 대기열의 **자동 생성 시작**을 누릅니다. 처음에는 기준만 기록하고 이후 세이브 저장에서 이적을 감지하면 자동 생성·저장합니다.

Codex CLI 및 사용 계정에서 이미지 생성 도구를 사용할 수 있어야 합니다. 얼굴·키트 이미지는 저장소에 포함하지 않습니다.

## 생성 범위

새 설정의 기본값은 **내가 맡은 구단만 · 방출·영입 모두**입니다. 기존 버전의 설정은 기존 영입 방향·구단·선수 선택을 유지하여 옮깁니다.

프리셋은 내가 맡은 구단만, 모든 이적, 5대 리그만, 프리미어리그만, 프리미어리그 빅6만, 세리에 A만, 라리가만, 리그앙만, 분데스리가만입니다. **직접 설정**에서는 세이브 구단을 검색하거나 ID로 추가하고 구단별 방향을 선택합니다.

**맨유 ‘방출된 선수만’ → 맨유에서 아스날로 이적**이면 아스날을 선택하지 않아도 아스날 유니폼으로 생성합니다. 영입은 새 구단, 방출은 이전 구단을 기준으로 판단합니다. 무소속 상태에는 생성하지 않고 이후 새 구단에 들어가면 이전 구단을 이어 비교합니다.

리그 참가 구단은 고정된 현실 명단 대신 세이브의 현재 시즌 경기일정과 대회 DB ID로 확인합니다. 해당 리그 일정/리더를 읽을 수 없으면 범위 화면에 안내하고 확인하지 못한 구단을 임의로 포함하지 않습니다.

## 검증 상태

자동 테스트 **155개**가 통과했습니다. 세이브별 기록 분리·기존 DB 연결·과거 시점 기준 분리, 골키퍼 판별·전용 키트 선택·누락 시 호출 차단, 개별 지시의 작업별 우선순위와 편집 중 합성 방지까지 검증했습니다. Linux 화면에서는 자동 생성 실행 중 개별 지시 저장, 세이브 변경에 따른 기록 전환, 과거 시점의 자동 기준 분리, 고급설정과 관리 도구를 확인했습니다. 이 확인에는 시험용 JSON을 사용했으며 실제 Codex 이미지 요청은 보내지 않았습니다. 사용자는 이전 버전의 Windows 이적 감지 → 생성 → 게임 적용을 확인했습니다. 이번 버전의 실제 FM 골키퍼 생성·Windows 화면과 EXE 빌드는 추가 확인이 필요합니다.

v0.4.2는 등록 팀이 그대로이고 임대가 아닌 선수의 현재 계약 구단만 바뀌는 에디터 이동도 비교합니다. 최초 읽기나 기존 버전에서 추가 계약 정보를 처음 읽은 시점에는 과거 변화를 추측하지 않습니다. ‘신규 작업 0개’가 나오면 로그의 **감지 진단**에서 지정 선수의 이전/현재 소속·등록 팀·계약 구단·범위 제외 사유를 확인하세요. **작업 대기열 → 관리 도구 → 감지 진단 내보내기**로 JSON을 내보낼 수 있고 작업 폴더의 `latest_detection.json`에도 자동 저장됩니다.

v0.4.1부터 **페이스팩 저장 폴더는 처음에도 비어 있을 필요가 없습니다.** 기존 팩을 선택하면 생성한 선수의 `ID.png`와 일반/r-ID 초상화 매핑만 갱신합니다. 다른 파일명·하위 경로·다른 종류의 XML 매핑은 유지하며, 백업 복구도 선택한 작업의 선수만 되돌립니다. 원본 얼굴 폴더와 저장 폴더를 같은 곳으로 지정할 수 있습니다.

v0.4.x에서 업데이트하려면 앱을 닫고 `git pull --ff-only` 후 `start_windows.bat`로 실행하세요. 의존성 재설치는 필요 없습니다. 기존 설정을 유지하고, 감시 시작 시 이 앱이 관리하는 기존 `ID_작업번호.png`를 재합성 없이 `ID.png`로 변환하며 XML도 맞춥니다. 이전 파일은 백업합니다.

영문 이름은 게임 이름 풀의 라틴 문자 표기를 우선 사용합니다. 없으면 동일 합성 요청에서 Codex가 영문 표기/로마자 표기를 반환하므로 공식 철자와 다를 수 있습니다. 선수별 이름으로 수정할 수 있습니다.

v0.3.2는 fmsave를 0.12.6으로 올리고 FM27 `27.1.0+2505117`을 호환 대상으로 추가했습니다. 이전 버전에서 ‘검증 대상 외 게임 빌드’가 표시됐다면 앱을 닫고 `git pull --ff-only`, `setup_windows.bat` 순서로 업데이트하세요. 이 빌드의 `known_build`가 false여도 선수·구단을 엄격 검사로 읽도록 하며, 모든 게임 데이터의 호환성을 보장한다는 뜻은 아닙니다.

상세 사용법, 지원 빌드, 파일 규칙과 남은 기능은 [한국어 설명서](README.ko.md)를 확인하세요.

```console
python -m unittest discover -s tests -v
```

비공식 팬 프로그램이며 Sports Interactive 또는 SEGA의 공식 제품이 아닙니다. 세이브 읽기에 fmsave, 이미지 후처리에 Pillow를 사용합니다.
