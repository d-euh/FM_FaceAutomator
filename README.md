# FM Face Automator

FM27 세이브 저장 후 이적을 감지하여 Codex CLI로 페이스온 합성을 요청하는 독립형 Windows 데스크톱 프로그램의 **미리보기 버전(v0.17.0)**입니다.

설정 파일이 없는 최초 실행에는 **폴더 · 연결** 설정 창이 자동으로 열립니다. 이후 실행 및 기존 설정이 있는 경우에는 홈 화면으로 시작합니다.

앱 창에는 FFA 원형 화살표 아이콘을 사용합니다. 고해상도 원본에서 Windows 배율별 ICO를 생성하며, 실행 중인 창에는 256px 이미지를 적용합니다. `build_windows.bat`는 빌드 후 EXE 내부 아이콘을 검사하고 탐색기에 해당 파일의 갱신을 알립니다. 성공 메시지 `Verified FFA icon in:`을 확인하세요. 탐색기에 이전 Python 아이콘이 남으면 EXE를 임시로 다른 이름으로 복사해 확인할 수 있습니다. 새 이름에서 FFA가 보이면 기존 경로의 아이콘 캐시 문제입니다. 아이콘 재생성은 `python scripts/generate_icons.py`로 실행합니다.

v0.17.0은 게임의 실제 선수단 관계를 조회하는 **1군·리저브·유소년 필터**를 이적 감지 범위에 연결합니다. 기본값은 모두 포함이며, 구분을 제한하면 생성 전에 게임에서 등록 팀을 확인합니다. 영입은 새 팀, 방출은 이전 팀을 기준으로 같은 구단/이동 방향과 함께 판정합니다. 확인하지 못한 작업은 AI 호출 없이 보류합니다. **팀 조회 플러그인 0.4.2는 게임 종료 후 `install_team_bindings.bat`로 설치해야 합니다.** 기존 페이스온 새로고침 DLL은 그대로입니다.

새 작업은 같은 세이브 업데이트에서 추가된 작업끼리만 담당 구단 관련 영입·방출을 우선하며, 기존 대기열의 수동 순서 뒤에 붙습니다. 새 작업이 실제 추가되면 완료 항목을 대기열에서 자동으로 숨기고 작업·호출 이력과 PNG/XML은 보존합니다. 게임 진행·저장 때문에 팀 조회나 적용을 기다리는 작업은 **게임 대기**로 표시하고 안정된 뒤 자동 재개합니다. 선택 재시도도 대기를 유지하며, 합성된 결과는 추가 AI 호출 없이 저장만 재개합니다. **팀 조회 DLL 0.4.2**은 연속된 안전 상태에서 묶음 내 팀마다 반복하던 2초 대기를 줄입니다. 게임 종료 후 **install_team_bindings.bat**로 재설치하세요.

합성 전에 확인한 선수단 판정은 작업에 보관합니다. 저장 직전에는 세이브 스냅샷·선수 등록 정보·선택 범위·게임 세션과 데이터 세대가 같으면 기존 판정을 재사용합니다. 단순 진행/경기 처리만으로는 데이터 세대를 바꾸지 않으며, 세이브 로딩·담당 구단 변경·알 수 없는 게임 상태에서는 판정을 다시 확인합니다. 팀 조회 DLL **0.4.2**가 이 구분을 제공합니다. 이전 DLL은 기존의 엄격한 조회 세대 검사를 사용합니다. 판정 근거가 저장되지 않은 기존 작업은 한 번 확인한 뒤부터 재사용합니다.

Steam 빌드 **26620374**용 실험적 게임 갱신 플러그인은 `install_live_refresh.bat`로 설치합니다. BepInEx 6 IL2CPP x64 be.793 이상이 필요하며, 게임을 종료한 상태에서 설치한 뒤 앱의 **생성 후 자동 새로고침**을 켭니다. [설치·테스트·진단 안내](plugin-src/FMFaceRefresh/README.md)를 확인하세요. 진단 내보내기는 `export_diagnostics.bat` 또는 **우측 상단 폴더 · 연결 → 문제 해결 펼치기 → 문제 진단 저장**입니다.

1. 이 저장소를 `D:\FMFaceAutomator`에 내려받습니다.
2. Python 3.12 이상(Tk 및 Python Launcher 포함)을 준비합니다.
3. `setup_windows.bat`를 실행한 뒤 `start_windows.bat`를 실행합니다.
4. Codex CLI를 설치하고 앱의 **폴더 · 연결 → ChatGPT 로그인**을 누릅니다. 자동 입력한 실행 파일 경로가 다르면 먼저 바꿔 주세요.
5. **이적 감지 범위** 탭에서 범위를 정하고 **설정 저장** 후 홈이나 대기열의 **자동 생성 시작**을 누릅니다. 처음에는 기준만 기록하고 이후 세이브 저장에서 이적을 감지하면 자동 생성·저장합니다.

Codex CLI 및 사용 계정에서 이미지 생성 도구를 사용할 수 있어야 합니다. 얼굴·키트 이미지는 저장소에 포함하지 않습니다.

## 직접 생성

이적을 기다리지 않고 **직접 생성 → 목록 불러오기 → 선수 선택 → 생성 요청**으로 한 명을 생성할 수 있습니다. 이미 목록을 읽었다면 이름·영문 이름·현재 구단·선수 ID로 바로 검색하세요. **유니폼 구단** 기본값은 선택한 선수의 현 소속팀이며, 다른 구단을 검색해 선택할 수 있습니다. **현 소속팀**으로 기본값에 돌아옵니다. 이 선택은 합성에 사용할 구단이며 실제 게임의 소속을 바꾸지 않습니다.

**참조 사진**은 선택 사항입니다. 왼쪽 위에서 선수를 선택한 뒤 아래의 **사진 불러오기**로 얼굴 참조를 넣으세요. 사진은 비율을 유지해 미리 보며 **제거**로 기존 자동 검색 방식에 돌아갑니다. 다른 선수로 바꾸면 이전 사진은 선택 해제됩니다. 선택한 사진은 해당 요청에만 적용하며 원본 파일을 변경하지 않습니다. 작업 기록에 보관한 PNG 사본이 Codex의 첫 번째 이미지인 `original.png`로 전달되고, 로컬 구단 키트가 있으면 두 번째 이미지로 전달됩니다. 키트가 없으면 같은 요청에서 웹으로 찾습니다. 이 사본이 손상되거나 사라지면 AI 호출 전에 보류하며 임의 웹 사진으로 대체하지 않습니다.

이 작업에만 적용할 지시는 선택 입력입니다. 공통 지시와 함께 전달하며 개별 지시가 우선합니다. 자동 이적 범위·제외 선수·나이 제한과 별개로 요청합니다. 호출 상한·재생성 간격은 유지하고 세이브 업데이트 횟수를 기다리지는 않습니다. 감시가 꺼져 있으면 요청한 작업만 처리하고, 자동 감시 중이면 대기열에 추가해 현재 합성 이후 차례로 처리합니다. 결과는 같은 저장 폴더에 `ID.png`와 config.xml 매핑으로 저장합니다.

같은 선수의 미완료 대기 요청은 새 요청으로 대체합니다. 생성·저장·개별 지시 편집 중인 작업은 완료한 뒤 다시 요청하세요. 선택 후 실제 소속·인물 정보가 바뀌면 다시 선택해야 하며, 생성 중 이적한 결과는 이전 소속의 작업과 같이 적용을 취소합니다.

## 중복 페이스팩 우선순위

**기존 페이스팩 폴더**에 여러 팩을 담은 상위 폴더를 지정할 수 있습니다. 같은 선수 ID의 매핑이 여러 팩에 있으면 `config.xml`이 있는 폴더의 상대 경로를 비교해 이름 순서상 뒤인 팩을 고릅니다. 예를 들어 `A_pack`과 `Z_pack`에서는 `Z_pack`을 선택합니다. 각 경로 단계는 대소문자 구분 없는 문자열 순서로 비교하며, 탐색기의 숫자 자연 정렬·사진 파일명·파일 수정일은 사용하지 않습니다. XML이 다른 하위 폴더의 사진을 가리켜도 XML 폴더가 기준입니다.

이 기준은 [FM26 그래픽 모딩 가이드](https://www.patreon.com/skogr/posts/how-to-fix-where-163716958)와 [FMAX의 FM27 그래픽 문서](https://hexase1-ship-it.github.io/fmle/en/graphics.html)에 설명된 후순 이름 팩 우선 규칙을 재현합니다. 예전 FM의 앞선 이름 팩 우선 안내와 다릅니다. 현재 플러그인은 게임이 선택한 사진 경로를 조회하지 않으므로 등록 경로 순서·캐시·게임 패치에 따른 모든 동작의 일치를 보장하는 기능은 아닙니다. 이번 변경은 실제 FM27 화면과의 대조가 필요합니다.

지정한 상위 폴더에 앱이 만든 팩이 있으면 선택 대상에 포함하고 `backups`와 작업 기록은 제외합니다. 자동 경로 찾기는 생성 팩을 새 원본 기본값으로 선택하지 않습니다. 우선순위가 높은 팩에 매핑만 있고 사진이 없으면 낮은 팩의 사진으로 임의 대체하지 않고 기존 사진 누락 처리로 넘깁니다. **같은 팩의 XML 안에서 같은 선수에게 서로 다른 사진을 중복 지정한 오류**는 계속 보류합니다.

XML 매핑이 전혀 없는 선수에 한해 ID 파일명 검색을 호환 기능으로 유지하며 이때도 뒤인 폴더를 우선합니다. XML 없이 사진만 복사해 둔 상태가 게임에 적용된다는 의미는 아닙니다. 선택한 원본 경로는 작업 데이터의 `portrait_reference`에 남고, Codex에는 그 사진을 `original.png`로 복사해 전달합니다. 유니폼 선택 방식·출력 ID 파일명·config.xml 저장은 유지합니다.

## 키트 파일이 없을 때

설정한 키트 폴더가 비어 있거나 존재하지 않는 경우, 해당 구단·유형의 이미지가 없는 경우, 이전 고정 선택 파일이 삭제된 경우에는 키트 누락만으로 멈추지 않고 Codex의 `--search`를 켭니다. 같은 요청에서 유니폼을 찾은 뒤 이미지 도구에 참조로 전달하도록 요청합니다. 웹에서 얼굴이나 키트 참조를 가져오는 요청은 Codex 작업 샌드박스의 네트워크 접근도 함께 허용하여 이미지 파일을 다운로드할 수 있게 합니다. 얼굴도 없으면 얼굴·키트를 함께 검색하며 별도 두 번째 AI 요청을 만들지 않습니다.

웹 키트의 시즌은 **2026/27(26/27)**로 고정합니다. 게임이 2028년 이후여도 바뀌지 않으며, 현재 최신 시즌·다른 시즌·미확정 콘셉트 디자인을 대체품으로 쓰지 않도록 요청합니다. 홈·원정·서드와 골키퍼 유형을 구분하고 구단·제조사의 공식 자료를 우선합니다. 다른 구단 유니폼을 지정한 직접 생성은 **요청한 유니폼 구단**으로 검색합니다.

Codex가 실제 참조 이미지 `kit.png`와 `kit-source.json`을 저장해야 합니다. 출처 파일에는 정확한 시즌 `2026/27`, 구단 ID, 유형, 확인한 구단명, HTTPS 원문·이미지 URL이 필요합니다. 시즌·구단·유형 불일치, 출처 누락, 손상된 이미지는 생성 완료로 적용하지 않습니다. 도구를 사용할 수 없거나 정확한 키트를 찾지 못하면 사유를 표시하며 유료 API나 다른 시즌으로 전환하지 않습니다. 실제 검색을 시작한 요청은 사용량이 발생할 수 있으며 실패한 AI 검색을 자동 반복하지 않습니다.

이미 있는 로컬 키트는 기존 선택 방식을 유지합니다. 로컬 파일은 시즌 메타데이터가 없어 앱이 실제 시즌을 판별하지 못하므로 **26/27 자료를 지정하세요.** 손상된 로컬 이미지나 잘못된 폴더 설정은 누락과 구분해 합성 전 점검에서 안내합니다. 검색 출처 기록과 파일 형식을 검사하는 기능이며 앱이 사진을 시각적으로 분석해 실제 시즌·로고 정확성까지 독립 검증하는 기능은 아닙니다.

다운로드한 키트와 출처는 작업별 폴더에 보관합니다. 후처리·저장 실패 후 재시작/재시도에서도 검증된 참조와 완성 원본을 재사용하며 추가 AI 호출을 하지 않습니다. 저장 직전에도 웹 키트 출처를 재확인합니다. 기존 로컬 팩의 파일이나 config.xml은 검색 참조를 수집하는 과정에서 수정하지 않습니다.

## 사진이 없는 선수

로컬 페이스팩에 선수 사진이 없으면 Codex의 `--search`를 켜고 선수 이름·영문 이름·생년월일·게임 소속을 참고해 실제 얼굴 사진을 찾도록 요청합니다. 선택한 유니폼 구단은 얼굴의 신원 확인 근거와 구분합니다. `original.png`와 HTTPS 출처를 기록한 `face-source.json`이 없으면 완료로 적용하지 않습니다. 기존 로컬 사진이 있으면 그 사진을 사용하며, 중복·손상된 사진을 사진 없음으로 취급하지 않습니다.

생성선수로 확인된 인물은 다른 실존 인물의 얼굴로 대체하지 않습니다. 웹 검색·사진 가져오기·이미지 참조 도구가 사용 불가하거나 신원을 확인할 수 없으면 보류하며 유료 API로 전환하지 않습니다. 검색 요청도 Codex 사용량이 발생할 수 있고, 보류한 AI 요청을 자동으로 반복하지 않습니다. 사진과 출처 파일의 형식은 확인하지만 사진 속 인물이 맞는지를 앱이 시각적으로 자동 판정하지는 않습니다. 실제 웹 검색과 생성의 성공 여부는 사용자의 Codex CLI 도구·권한에 따라 달라집니다.

## 이적 감지 범위

새 설정의 기본값은 **내가 맡은 구단만 · 방출·영입 모두**입니다. 기존 버전의 설정은 기존 영입 방향·구단·선수 선택을 유지하여 옮깁니다.

프리셋은 내가 맡은 구단만, 모든 이적, 5대 리그만, 프리미어리그만, 프리미어리그 빅6만, 세리에 A만, 라리가만, 리그앙만, 분데스리가만입니다. **감지 대상** 드롭다운의 **직접 설정**에서는 왼쪽에서 세이브 구단을 검색하거나 ID로 추가하고 구단별 방향을 선택합니다. 오른쪽의 선수 개별 대상·제외 목록은 다른 프리셋에서도 사용할 수 있습니다. 상단의 **목록 불러오기**는 구단과 선수 목록을 함께 갱신합니다. 페이지 전체 스크롤 대신 각 목록의 스크롤을 사용하며 하단 **설정 저장**을 눌러 반영합니다.

### 이적 유형 선택

상단의 **포함할 이적 유형**에서 생성할 유형을 체크하고 **설정 저장**을 누르세요. **임대 이동**은 임대 이적과 임대 복귀를 함께 포함하며, 영입·방출은 **이동 방향**에서 선택합니다. 두 유형 중 하나만 켜 둔 기존 설정은 부분 선택으로 표시되며, 체크박스를 조작할 때까지 기존 선택을 유지합니다. 임대일 가능성이 있는 미확인 이동도 처리하지 않으려면 **유형 미확인**도 해제하세요. 기존 프리셋·구단별 방향·선수 개별 설정에 추가로 적용되며, 프리셋을 바꾸어도 유형 선택은 유지됩니다. 기본값은 세 항목 모두 선택입니다.

| 유형 | 판정 기준 |
| --- | --- |
| 완전 이적 | 확인된 비임대 소속·계약 변경. 자유계약 영입도 포함합니다. |
| 임대 이적 | 새 구단에서 임대 중임을 확인한 이동. 다른 구단으로의 재임대도 포함합니다. |
| 임대 복귀 | 이전 임대가 끝나고 확인된 원소속 구단으로 돌아온 이동입니다. |
| 유형 미확인 | 이전/현재 임대 상태·계약 정보가 부족하거나 서로 맞지 않아 구분할 수 없는 이동입니다. |

현재와 이전의 소속·임대 상태·계약 구단을 함께 비교합니다. 정보가 없을 때 완전 이적으로 추측하지 않습니다. 유형 도입 전 생성된 대기 작업은 과거 상태를 복원할 수 없으면 **유형 미확인**으로 표시합니다. 임대가 끝난 뒤 원소속이 아닌 다른 구단에 비임대 계약으로 들어간 경우는 완전 이적으로 구분합니다. 같은 구단에서 임대가 완전 이적으로 전환되어 소속이 그대로라면 새 작업을 만들지 않습니다.

유형 조건은 자동 이적 작업에 적용하며 선택한 선수도 이 조건을 따릅니다. **직접 생성**과 **현재 선수 생성 대기**는 이적 이벤트를 요구하지 않는 명시적 요청이므로 유형 조건을 적용하지 않습니다. 모두 해제하면 자동 이적 생성이 제외됩니다. 기존 대기·저장 대기 작업도 실행/적용 전 현재 조건을 다시 확인하며 이미 저장한 사진은 삭제하지 않습니다. 제외된 이동을 나중에 포함하도록 바꾸어도 과거 작업을 새로 만들지는 않습니다.

대기열의 **이적 유형** 열과 감지 진단에서 판정을 확인할 수 있습니다. 진단 보고서에는 분류 근거와 이전·현재 임대/계약 정보도 남깁니다. 유소년·1군 구분은 이번 변경에 포함하지 않습니다.

**맨유 ‘방출된 선수만’ → 맨유에서 아스날로 이적**이면 아스날을 선택하지 않아도 아스날 유니폼으로 생성합니다. 영입은 새 구단, 방출은 이전 구단을 기준으로 판단합니다. 무소속 상태에는 생성하지 않고 이후 새 구단에 들어가면 이전 구단을 이어 비교합니다.

리그 참가 구단은 고정된 현실 명단 대신 세이브의 현재 시즌 경기일정과 대회 DB ID로 확인합니다. 해당 리그 일정/리더를 읽을 수 없으면 범위 화면에 안내하고 확인하지 못한 구단을 임의로 포함하지 않습니다.

```powershell
.\export_team_bindings.bat
```

조회는 게임 메인 스레드에서 검증된 게임 상태 정책을 통과하고 2초간 안정된 뒤 시작합니다. 게임이 실제로 제공한 Human.Team/MainManager.Team 바인딩이 540일 때만 진단을 시작하며, 1군에서 반환된 두 유소년 참조가 기존 통제 실험의 28346·28347과 일치할 때만 그 두 팀을 추가 조회합니다. 이 숫자는 검증용 사례이며 전 구단의 슬롯 규칙이나 고정 매핑이 아닙니다.

팀마다 고유 ID·이름·1군 여부·팀 종류 값/문자열·구단 고유 ID·유소년 참조를 읽습니다. 임의 메모리 오프셋이나 숫자 변환을 사용하지 않습니다. DynamicNumber의 SignedWhole/UnsignedWhole/FloatingPoint를 구분하며 큰 정수 정밀도를 보존합니다. 유효하지 않은 숫자를 ID 0으로 만들지 않고, 실수를 잘라 고유 ID로 사용하지 않습니다.

조회용 노드는 매번 고유 이름으로 만든 임시 바인딩에 한정합니다. 이미 존재하는 UI 값을 덮어쓰지 않으며, 조회 후 Group.Dispose와 해당 노드 Remove를 실행합니다. 그룹 개수·생성/제거 카운터를 보고서에 담습니다. 진행/로딩 상태 변경·15초 시간 초과·오류 시에도 정리를 시도하고 추가 조회를 중단합니다. 전체 진단 시작 대기는 10분으로 제한합니다. 알 수 없는 서명이나 span 생성자가 있으면 바인딩을 만들기 전에 중단하고 API 형식을 기록합니다. 세이브·게임 플레이 명령·페이스팩·AI 요청은 수정/실행하지 않습니다.

새 보고서의 `probe`에 실제 결과와 오류가 포함됩니다. 모의 테스트 통과나 단순 조회 완료 상태만으로 전 구단 분류 성공을 주장하지 않습니다. 세 팀의 실제 고유 ID·팀 종류·정리 결과를 확인한 뒤 자동 필터에 연결합니다.

### 선수단 구분 필터 사용 (v0.17.0 / 팀 조회 DLL 0.4.2)

앞선 실게임 보고서에서 맨유 세 팀의 조회와 정리를 확인했습니다. 성인 팀 native index 540은 IsFirstTeam=true, U21 28346은 Club.ReservesTeam, U18 28347은 Club.YouthTeam과 일치했습니다. 각 팀의 고유 ID는 680 / 2000778736 / 2000778737로 내부 인덱스와 다릅니다. 조회 그룹 3개·자체 바인딩 3개가 모두 정리됐습니다. 이 결과를 바탕으로 요청한 팀을 일반적으로 조회하는 연결을 앱에 구현했습니다.

1. FM27을 종료하고 업데이트한 뒤 `install_team_bindings.bat`를 실행합니다. 기존 새로고침 플러그인을 재설치할 필요는 없습니다.
2. 게임을 실행하고 **앱에 연결한 동일한 세이브**를 불러옵니다.
3. 앱의 **이적 감지 범위 → 선수단**에서 포함할 `1군 / 리저브 / 유소년`을 체크하고 설정을 저장합니다. 기본값은 모두 포함입니다.
4. 기존대로 자동 생성을 시작합니다. 최초에는 기준만 기록하고 이후 이적부터 비교합니다. 별도의 선수단/프로필 화면 방문이나 진단 내보내기는 필요 없습니다.

`내가 맡은 구단만 + 영입만 + 1군`이면 담당 구단의 1군에 들어온 선수만 생성합니다. 담당 구단에서 나간 선수를 고른 경우에는 이전 팀을 기준으로 판단합니다. 예를 들어 맨유 1군 방출을 선택하면 아스날이 선택되지 않아도 맨유 1군 → 아스날 이적이 포함됩니다. 맨유 U18 → 아스날 1군은 맨유 1군 방출에 포함되지 않습니다. 구단/선수 선택은 합집합이며 이적 유형·나이 제한은 함께 적용됩니다. 직접 생성 요청은 자동 감지 범위와 별개입니다.

판정은 `IsFirstTeam`과 해당 구단의 리저브/유소년 팀 참조를 사용합니다. 나이·계약 종류·슬롯 번호·현지화된 이름·특정 팀 종류 숫자를 전 구단 규칙으로 사용하지 않습니다. U21이 리저브 참조와 최고 유소년 참조 양쪽에 나타나면 구단의 명시적 리저브 참조를 우선합니다. 검증된 참조가 없는 B팀/별도 하위 팀, 등록 팀 누락, 대상 방향의 등록 팀과 구단이 맞지 않는 계약 변경, 다른 세이브가 열린 경우 등은 구분 미확인으로 보류합니다.

자유계약으로 무소속 기간을 거쳐 새 구단에 입단해도 방출은 이전 구단에서 마지막으로 확인한 등록 팀을, 영입은 새 구단의 실제 등록 팀을 기준으로 판정합니다. 방출 전에 등록 정보가 누락되더라도 보관된 마지막 유효 기록을 사용합니다. 새 구단 등록이 확인되지 않으면 기존 작업을 보류하고 이후 세이브에서 다시 확인합니다. 선수단을 제한한 상태에서 방출 방향만 대상인데 이전 등록 팀 기록이 없으면 해당 이동은 감지 알림과 생성 대기열에서 제외합니다. 같은 이동이 선택한 구단의 영입 조건에도 해당하면 새 구단 선수단 기준으로 처리합니다. 기존의 미호출 보류 작업도 자동으로 대기열에서 제외하며 이력은 보존합니다. 이미 AI를 호출했거나 결과가 보관된 작업은 이 정리 대상에서 제외합니다. 선수단을 모두 포함하면 이전 선수단 기록 없이도 기존대로 감지합니다.

구분을 제한했는데 게임/조회 DLL에 연결되지 않으면 작업에 보류 이유를 표시하고 AI 합성을 호출하지 않습니다. 게임이 안정된 뒤 자동으로 재시도합니다. 이미 생성한 이미지는 보존하며 적용 전에 범위를 다시 확인합니다. 모두 포함한 기본 설정에서는 이 추가 조회가 필요하지 않습니다.

조회는 같은 Windows 사용자 계정의 LocalAppData 아래 파일 프로토콜로 통신합니다. 요청은 4개 팀 이하이며 게임 상태·세션/세대·만료 시간을 검사합니다. 실제 고유 ID를 사용해 요청 구단과 담당 구단을 확인하고, 캐시는 게임 세대와 세이브 스냅샷별로 분리합니다. 실행 중인 게임에 앱과 동일한 세이브를 불러와야 합니다. 이름만 같은 다른 세이브를 연결하지 마세요. 임시 바인딩은 고유 경로로 생성·정리하며, 정리 오류가 있으면 해당 게임 세션에서 새 조회를 중단합니다. 플레이 명령이나 세이브 파일을 수정하지 않습니다.

서로 다른 구단의 다양한 하위 팀 구조를 실게임에서 모두 시험한 것은 아닙니다. 정확한 관계가 확인된 경우에만 분류하며 그 외에는 보류합니다. 이 버전의 앱/로컬 파일 통신/방향별 필터는 모의 게임 API와 단위 테스트로 검증했습니다. 문제 발생 시 `export_team_bindings.bat`로 최근 조회 결과를 내보낼 수 있습니다.
