# FM Face Automator

FM27 세이브 저장 후 이적을 감지하여 Codex CLI로 페이스온 합성을 요청하는 독립형 Windows 데스크톱 프로그램의 **미리보기 버전(v0.12.0)**입니다.

v0.12.0은 **폴더 · 연결** 탭을 제거하고 우측 상단 버튼으로 여는 설정 창으로 옮깁니다. 진단·선수 목록·백업 도구는 설정 창의 **문제 해결 펼치기** 안에 용도와 함께 둡니다. 새 **직접 생성** 탭에서는 선수를 검색하고 유니폼 구단(기본값: 현 소속팀)과 개별 지시를 지정해 이적 없이 생성할 수 있습니다. 원본 사진이 없는 실제 선수는 같은 Codex 요청에서 웹 검색으로 얼굴 사진과 출처를 확보하도록 요청합니다. 확인할 사진·출처가 없거나 웹/이미지 도구를 사용할 수 없으면 보류합니다. DLL 재설치는 필요 없습니다.

v0.11.1은 대기열 하단을 **선택 재시도 / ⋯ 작업 메뉴**로 정리하고 우측에 **모든 대기열 삭제**를 추가합니다. 작업 메뉴와 우클릭에서 재시도·삭제·위로 이동·아래로 이동·맨 위로·유니폼 변경을 실행할 수 있습니다. 대기 작업을 드래그해 생성 순서를 바꾸며, 놓기 전에는 적용하지 않고 Escape로 취소합니다. 순서는 재시작 후에도 유지됩니다. 전체 삭제는 생성·저장·편집 중인 작업을 보호하고 저장된 사진·config.xml·호출 이력을 보존합니다. 개별 지시 창이 표시되기 전에 입력을 잠가 내용이 비던 문제도 수정했습니다. DLL 재설치는 필요 없습니다.

v0.11.0은 생성 범위와 대기열 조작을 정리합니다. 구단 검색·선택 목록을 각각 3행·2행으로 줄이고 그 아래 **선수 직접 설정 / 선택한 선수**를 추가했습니다. 이름·영문 이름·소속팀·ID로 검색해 생성 대상 또는 제외 선수를 추가합니다. 기존 지정·제외 선수는 목록으로 이어받으며, 고급설정의 세 ID 입력칸은 제거했습니다. r- 초상화는 기존 config.xml 또는 명확한 r-ID 파일명으로 판별합니다.

대기열 상단은 **자동 생성 시작 / 전체 재시도 / 작업 종료 후 멈춤**, 좌측 하단은 **선택 재시도 / ⋯ 작업 메뉴**, 우측 하단은 **모든 대기열 삭제**입니다. 작업 메뉴와 우클릭은 같은 조작을 제공하며, 대기 작업을 드래그하거나 메뉴에서 이동해 실제 생성 순서를 바꿀 수 있습니다. 순서는 재시작 후에도 유지됩니다. 더블클릭으로 개별 지시 또는 결과를 엽니다. 선택 재시도는 다른 대기 작업을 실행하지 않고, 전체 재시도는 실패·보류·중단·저장 실패·저장 대기만 처리합니다. 저장된 이미지는 추가 AI 호출 없이 재사용합니다. 실행 중이거나 편집 중인 작업은 삭제할 수 없으며, **대기열 삭제는 저장된 사진·config.xml·호출 이력을 지우지 않습니다.**

홈에 **페이스온 새로고침**과 ‘누르면 게임 내에 페이스온 변경사항이 적용됩니다.’ 설명을 배치했습니다. 자동 새로고침 설정과 별개로 수동 요청을 보낼 수 있으며 AI를 호출하지 않습니다. 관리 도구 버튼을 제거하고 **문제 진단 저장 / 선수 목록 저장 / 백업 복원**은 폴더 · 연결로 옮겼습니다. 현재 선수 일괄 생성 대기는 생성 범위 탭에 있습니다. 기록 버튼은 **작업 기록 펼치기**로 바꾸고 반복 설명을 줄였습니다. 앱만 업데이트하면 되며 DLL은 0.2.3 그대로입니다.

추가 조건·호출량은 **고급설정 팝업**으로 분리합니다. 생성 범위의 **범위 저장 아래 왼쪽** 버튼을 눌러야 열리며 상단 탭에는 나타나지 않습니다. 닫기·X·Esc로 닫고 버튼으로 다시 열 수 있습니다. 기본값은 나이 전체·호출/재생성 제한 없음·생성 대기 없음입니다. 감시 간격은 **세이브 업데이트 횟수**로 정하며 기본 **1회(매 업데이트)**입니다. 2회 이상이면 각 저장의 이적을 기록하고 지정 횟수마다 누적 작업을 처리합니다. 최초 기준 읽기는 횟수에서 제외합니다.

## Windows에서 실행

Steam 빌드 **26620374**용 실험적 게임 갱신 플러그인은 `install_live_refresh.bat`로 설치합니다. BepInEx 6 IL2CPP x64 be.793 이상이 필요하며, 게임을 종료한 상태에서 설치한 뒤 앱의 **생성 후 자동 새로고침**을 켭니다. [설치·테스트·진단 안내](plugin-src/FMFaceRefresh/README.md)를 확인하세요. 진단 내보내기는 `export_diagnostics.bat` 또는 **우측 상단 폴더 · 연결 → 문제 해결 펼치기 → 문제 진단 저장**입니다.

1. 이 저장소를 `D:\FMFaceAutomator`에 내려받습니다.
2. Python 3.12 이상(Tk 및 Python Launcher 포함)을 준비합니다.
3. `setup_windows.bat`를 실행한 뒤 `start_windows.bat`를 실행합니다.
4. Codex CLI를 설치하고 앱의 **폴더 · 연결 → ChatGPT 로그인**을 누릅니다. 자동 입력한 실행 파일 경로가 다르면 먼저 바꿔 주세요.
5. **생성 범위** 탭에서 범위를 정하고 **범위 저장** 후 홈이나 대기열의 **자동 생성 시작**을 누릅니다. 처음에는 기준만 기록하고 이후 세이브 저장에서 이적을 감지하면 자동 생성·저장합니다.

Codex CLI 및 사용 계정에서 이미지 생성 도구를 사용할 수 있어야 합니다. 얼굴·키트 이미지는 저장소에 포함하지 않습니다.

## 직접 생성

이적을 기다리지 않고 **직접 생성 → 목록 불러오기 → 선수 선택 → 생성 요청**으로 한 명을 생성할 수 있습니다. 이미 목록을 읽었다면 이름·영문 이름·현재 구단·선수 ID로 바로 검색하세요. **유니폼 구단** 기본값은 선택한 선수의 현 소속팀이며, 다른 구단을 검색해 선택할 수 있습니다. **현 소속팀**으로 기본값에 돌아옵니다. 이 선택은 합성에 사용할 구단이며 실제 게임의 소속을 바꾸지 않습니다.

이 작업에만 적용할 지시는 선택 입력입니다. 공통 지시와 함께 전달하며 개별 지시가 우선합니다. 자동 이적 범위·제외 선수·나이 제한과 별개로 요청합니다. 호출 상한·재생성 간격은 유지하고 세이브 업데이트 횟수를 기다리지는 않습니다. 감시가 꺼져 있으면 요청한 작업만 처리하고, 자동 감시 중이면 대기열에 추가해 현재 합성 이후 차례로 처리합니다. 결과는 같은 저장 폴더에 `ID.png`와 config.xml 매핑으로 저장합니다.

같은 선수의 미완료 대기 요청은 새 요청으로 대체합니다. 생성·저장·개별 지시 편집 중인 작업은 완료한 뒤 다시 요청하세요. 선택 후 실제 소속·인물 정보가 바뀌면 다시 선택해야 하며, 생성 중 이적한 결과는 이전 소속의 작업과 같이 적용을 취소합니다.

## 사진이 없는 선수

로컬 페이스팩에 선수 사진이 없으면 Codex의 `--search`를 켜고 선수 이름·영문 이름·생년월일·게임 소속을 참고해 실제 얼굴 사진을 찾도록 요청합니다. 선택한 유니폼 구단은 얼굴의 신원 확인 근거와 구분합니다. `original.png`와 HTTPS 출처를 기록한 `face-source.json`이 없으면 완료로 적용하지 않습니다. 기존 로컬 사진이 있으면 그 사진을 사용하며, 중복·손상된 사진을 사진 없음으로 취급하지 않습니다.

생성선수로 확인된 인물은 다른 실존 인물의 얼굴로 대체하지 않습니다. 웹 검색·사진 가져오기·이미지 참조 도구가 사용 불가하거나 신원을 확인할 수 없으면 보류하며 유료 API로 전환하지 않습니다. 검색 요청도 Codex 사용량이 발생할 수 있고, 보류한 AI 요청을 자동으로 반복하지 않습니다. 사진과 출처 파일의 형식은 확인하지만 사진 속 인물이 맞는지를 앱이 시각적으로 자동 판정하지는 않습니다. 실제 웹 검색과 생성의 성공 여부는 사용자의 Codex CLI 도구·권한에 따라 달라집니다.

## 생성 범위

새 설정의 기본값은 **내가 맡은 구단만 · 방출·영입 모두**입니다. 기존 버전의 설정은 기존 영입 방향·구단·선수 선택을 유지하여 옮깁니다.

프리셋은 내가 맡은 구단만, 모든 이적, 5대 리그만, 프리미어리그만, 프리미어리그 빅6만, 세리에 A만, 라리가만, 리그앙만, 분데스리가만입니다. **직접 설정**에서는 세이브 구단을 검색하거나 ID로 추가하고 구단별 방향을 선택합니다.

**맨유 ‘방출된 선수만’ → 맨유에서 아스날로 이적**이면 아스날을 선택하지 않아도 아스날 유니폼으로 생성합니다. 영입은 새 구단, 방출은 이전 구단을 기준으로 판단합니다. 무소속 상태에는 생성하지 않고 이후 새 구단에 들어가면 이전 구단을 이어 비교합니다.

리그 참가 구단은 고정된 현실 명단 대신 세이브의 현재 시즌 경기일정과 대회 DB ID로 확인합니다. 해당 리그 일정/리더를 읽을 수 없으면 범위 화면에 안내하고 확인하지 못한 구단을 임의로 포함하지 않습니다.

## 검증 상태

자동 테스트 **220개**가 통과했습니다. 직접 생성의 범위 독립성·현 소속팀 기본값·지정 구단 키트와 ID 매핑·중복 요청 대체·호출 제한·이적/인물 변경 시 결과 보호를 확인했습니다. 사진 누락 시 검색 옵션·첨부 이미지 구성·출처 누락 시 적용 방지와 생성선수/중복 사진의 별도 처리도 검증했습니다. Linux 화면에서 별도 설정 창·문제 해결 펼치기·현 소속팀 선택·다른 구단 지정과 개별 지시·감시 중/정지 중 직접 생성을 점검했습니다. 시험용 데이터와 모의 CLI를 사용했으며 실제 AI 요청이나 웹 검색은 보내지 않았습니다. 실제 Codex 웹 사진 검색·합성, Windows 화면과 EXE 빌드는 사용자 환경에서 확인해야 합니다. 사용자는 이전 버전에서 Windows 이적 감지 → 생성 → 게임 적용과 새로고침을 확인했습니다.

v0.4.2는 등록 팀이 그대로이고 임대가 아닌 선수의 현재 계약 구단만 바뀌는 에디터 이동도 비교합니다. 최초 읽기나 기존 버전에서 추가 계약 정보를 처음 읽은 시점에는 과거 변화를 추측하지 않습니다. ‘신규 작업 0개’가 나오면 로그의 **감지 진단**에서 지정 선수의 이전/현재 소속·등록 팀·계약 구단·범위 제외 사유를 확인하세요. **우측 상단 폴더 · 연결 → 문제 해결 펼치기 → 문제 진단 저장**로 JSON을 내보낼 수 있고 작업 폴더의 `latest_detection.json`에도 자동 저장됩니다.

v0.4.1부터 **페이스팩 저장 폴더는 처음에도 비어 있을 필요가 없습니다.** 기존 팩을 선택하면 생성한 선수의 `ID.png`와 일반/r-ID 초상화 매핑만 갱신합니다. 다른 파일명·하위 경로·다른 종류의 XML 매핑은 유지하며, 백업 복구도 선택한 작업의 선수만 되돌립니다. 원본 얼굴 폴더와 저장 폴더를 같은 곳으로 지정할 수 있습니다.

v0.4.x에서 업데이트하려면 앱을 닫고 `git pull --ff-only` 후 `start_windows.bat`로 실행하세요. 의존성 재설치는 필요 없습니다. 기존 설정을 유지하고, 감시 시작 시 이 앱이 관리하는 기존 `ID_작업번호.png`를 재합성 없이 `ID.png`로 변환하며 XML도 맞춥니다. 이전 파일은 백업합니다.

영문 이름은 게임 이름 풀의 라틴 문자 표기를 우선 사용합니다. 없으면 동일 합성 요청에서 Codex가 영문 표기/로마자 표기를 반환하므로 공식 철자와 다를 수 있습니다. 선수별 이름으로 수정할 수 있습니다.

v0.3.2는 fmsave를 0.12.6으로 올리고 FM27 `27.1.0+2505117`을 호환 대상으로 추가했습니다. 이전 버전에서 ‘검증 대상 외 게임 빌드’가 표시됐다면 앱을 닫고 `git pull --ff-only`, `setup_windows.bat` 순서로 업데이트하세요. 이 빌드의 `known_build`가 false여도 선수·구단을 엄격 검사로 읽도록 하며, 모든 게임 데이터의 호환성을 보장한다는 뜻은 아닙니다.
