# FM Face Automator · v1.0

FM Newgen Face Studio와 연결하지 않는 독립형 Windows 데스크톱 프로그램입니다. 저장소에는 소스와 Windows 배포 ZIP 빌드 기능을 제공합니다. 받는 사용자는 배포 ZIP을 풀어 Python 설치 없이 실행할 수 있습니다. 미리 빌드한 Windows EXE는 이 저장소에 커밋하지 않습니다.

배포·설치·업데이트는 **[v1.0 빠른 시작 안내](docs/QUICK_START.ko.md)**를 참고하세요. Windows에서 `build_windows.bat`를 실행하면 **`dist\FMFaceAutomator-v1.0-windows-x64.zip`**을 만듭니다. 기존 `dist\FMFaceAutomator`는 교체하지 않습니다. 새 ZIP의 `update_windows.bat`로 프로그램 파일만 업데이트하며 기존 설정·작업 기록·페이스팩은 보존하고 교체한 프로그램 파일은 백업합니다. 받는 PC에서는 `install_game_plugins.bat`로 게임 연동 DLL을 설치하며 Python이 필요하지 않습니다.

설정 파일이 없는 최초 실행에는 자동 경로 검색 결과를 반영한 뒤 **폴더 · 연결** 설정 창이 자동으로 열립니다. 검색에 실패하거나 일부 경로를 찾지 못해도 창을 열어 직접 선택할 수 있습니다. 이후 실행 및 기존 설정이 있는 경우에는 홈 화면으로 시작합니다.

초기 자동 찾기는 이미 지정한 자료 경로의 전체 검색을 생략하고, 미설정 항목만 탐색합니다. 폴더 분류는 `config.xml` 앞부분 최대 256KiB의 매핑 종류를 참고하며 이미지별 존재 확인이나 전체 매핑 목록을 만들지 않습니다. 샘플에서 분류되지 않은 자료는 폴더를 직접 선택할 수 있습니다. 전체 매핑·중복·이미지 검증은 실제 자료를 사용하는 단계에서 수행하며 기존 설정·사진·작업 기록을 보존합니다.

**폴더 · 연결** 창은 파일·Codex와 이름 스타일 패널 아래에 공통 지시를 항상 표시합니다. 파일·Codex 제목 아래의 안내에 따라 연결 폴더를 확인하세요. **생성 후 자동 새로고침** 설정은 홈의 **페이스온 새로고침** 버튼 오른쪽에 있으며, 기존 설정값과 설정 저장 동작을 유지합니다.

앱 창에는 FFA 원형 화살표 아이콘을 사용합니다. 고해상도 원본에서 Windows 배율별 ICO를 생성하며, 실행 중인 창에는 256px 이미지를 적용합니다. `build_windows.bat`는 빌드 후 EXE 내부 아이콘을 검사하고 탐색기에 해당 파일의 갱신을 알립니다. 성공 메시지 `Verified FFA icon in:`을 확인하세요. 탐색기에 이전 Python 아이콘이 남으면 EXE를 임시로 다른 이름으로 복사해 확인할 수 있습니다. 새 이름에서 FFA가 보이면 기존 경로의 아이콘 캐시 문제입니다. 아이콘 재생성은 `python scripts/generate_icons.py`로 실행합니다.

새 작업은 같은 세이브 업데이트에서 추가된 작업끼리만 담당 구단 관련 영입·방출을 우선하며, 기존 대기열의 수동 순서 뒤에 붙습니다. 새 작업이 실제 추가되면 완료 항목을 대기열에서 자동으로 숨기고 작업·호출 이력과 PNG/XML은 보존합니다. 게임 진행·저장 때문에 팀 조회나 적용을 기다리는 작업은 **게임 대기**로 표시하고 안정된 뒤 자동 재개합니다. 선택 재시도도 대기를 유지하며, 합성된 결과는 추가 AI 호출 없이 저장만 재개합니다. **팀 조회 DLL 0.4.2**은 연속된 안전 상태에서 묶음 내 팀마다 반복하던 2초 대기를 줄입니다. 게임 종료 후 **install_team_bindings.bat**로 재설치하세요.

## 실행

### 재시작 없는 적용 사전 진단

Steam 빌드 **26620374**용 메타데이터 진단 플러그인을 별도로 제공합니다. `install_refresh_diagnostics.bat`로 설치하고 FM27을 한 번 실행한 뒤 `export_refresh_diagnostics.bat`로 결과를 내보냅니다. **아직 그래픽 새로고침은 실행하지 않습니다.** BepInEx 6 IL2CPP x64 be.793 이상이 필요합니다. 로더 자동 설치·교체는 하지 않으며 게임·세이브 파일을 보내지 않고 진단 JSON만 확인하는 절차입니다. 자세한 순서와 검증 한계는 [플러그인 안내](plugin-src/README.md)에 있습니다.

### 일반 앱 실행

배포 ZIP을 받은 사용자는 [빠른 시작 안내](docs/QUICK_START.ko.md)에 따라 EXE를 실행합니다. 아래 Python 설치 절차는 소스 코드에서 실행하는 경우에만 필요합니다.

감지 진단은 **우측 상단 폴더 · 연결 → 문제 해결 펼치기 → 문제 진단 저장**에 있습니다. 목록 높이가 줄어들더라도 하단 작업 버튼을 볼 수 있습니다.

1. [python.org](https://www.python.org/downloads/windows/)에서 Python 3.12 이상을 설치합니다. Tk와 Python Launcher를 포함하세요.
2. 저장소를 내려받고 `setup_windows.bat`를 실행합니다. 전용 `.venv`에 세이브 읽기 및 이미지 검증 라이브러리를 설치합니다.
3. [Codex CLI](https://developers.openai.com/codex/cli/)를 설치합니다. 사용 계정과 CLI 환경에서 이미지 생성 도구를 사용할 수 있어야 합니다.
4. `start_windows.bat`를 실행합니다. 최초 실행 시 `config.json`이 만들어집니다.
5. **폴더 · 연결 → ChatGPT 로그인**으로 브라우저 로그인을 완료합니다. 자동 입력한 세이브·얼굴·키트·출력·Codex 경로를 확인합니다. 찾지 못했거나 다른 위치를 쓰려는 항목만 직접 바꾸세요. 일반적 위치 밖에 자료가 있으면 **문제 해결 펼치기 → 자료 검색 위치**를 지정할 수 있습니다. 기존 페이스팩과 키트 폴더를 알고 있다면 비워 두어도 됩니다.
6. 생성 범위를 지정하고 **설정 저장** 후 홈에서 **자동 생성 시작**을 누릅니다. 감시 중에는 창을 열어 두세요. 프로그램을 다시 실행하면 감시 시작을 한 번 누릅니다.

`build_windows.bat`는 Windows x64에서 EXE·DLL 설치/업데이트 도구를 묶은 `dist\FMFaceAutomator-v1.0-windows-x64.zip`을 만듭니다. 빌드는 임시 위치에서 수행하므로 기존 설치 폴더의 설정·작업 기록은 건드리지 않습니다. 실제 Windows 빌드·게임 검증은 별도로 필요합니다. 배포 ZIP은 EXE 하나가 아닌 폴더 전체를 포함합니다.

## 자동 경로 입력

앱이 열리면 별도 검색 버튼이나 확인 팝업 없이 다음 위치를 읽고 미설정 항목의 기본값을 채웁니다. 세이브·자료 상위 폴더를 직접 지정한 뒤에도 자동 확인합니다.

- Windows 문서 폴더 등록 위치 및 OneDrive의 Sports Interactive/Football Manager 27 또는 Football Manager 2027
- 해당 게임의 games 폴더에서 가장 최근 수정된 `.fm` 세이브 (세이브를 아직 지정하지 않았을 때)
- 선택한 세이브의 games 옆 graphics, 현재 얼굴·키트 폴더, 자료 검색 위치
- PATH와 Windows npm 설치 경로의 실제 `codex.exe`

얼굴 폴더 후보가 여러 개면 매핑이 가장 많은 팩을 기본값으로 사용합니다. 키트는 여러 리그·팩을 함께 검색하도록 공통 상위 폴더를 사용합니다. 숫자 파일명만 있는 자료는 얼굴/키트 종류를 확정할 수 없어 직접 지정할 수 있습니다. 출력 기본값은 발견한 graphics 아래 `000_FMFaceAutomator`입니다. 이전에 직접 지정해 저장한 경로와 검색 중 사용자가 수정한 값은 덮어쓰지 않습니다.

자동 검색은 드라이브 전체를 읽지 않습니다. 발견할 수 없는 항목만 직접 입력하거나 옆의 **선택**으로 지정하세요. 원본 얼굴·키트 자료는 사용자가 보유한 파일을 사용하며 자동 다운로드하지 않습니다. Windows의 `.cmd`/`.bat`는 Codex 실행 대상으로 받지 않습니다.

## 원본 얼굴·유니폼 자료

기존 매핑에서 인식하는 형태는 다음과 같습니다. XML의 `from` 값을 파일명으로 사용하므로 사진 파일명이 선수 ID나 구단 ID일 필요는 없습니다.

```xml
<record from="photos/player_photo" to="graphics/pictures/person/900001/portrait"/>
<record from="photos/newgen_photo" to="graphics/pictures/person/r-900002/portrait"/>
<record from="manchester_h" to="graphics/pictures/team/20/kits/home"/>
```

유니폼 유형은 설정의 **홈 / 원정 / 서드**에서 고릅니다. 3D `kit_textures` 매핑은 2D 유니폼 참조와 구분하여 검색 결과에서 제외합니다. 2D 이미지나 실제 유니폼 사진을 참조로 사용할 수 있지만, 로고만 있는 폴더나 게임 기본 압축 리소스를 자동으로 유니폼 사진으로 바꾸지는 않습니다.

### 골키퍼 유니폼

세이브 리더의 `natural_positions` 및 `positions.gk`를 사용해 골키퍼를 판별합니다. 주 포지션이 GK이거나, 자연 포지션이 없는 경우 골키퍼 점수가 15 이상이며 다른 포지션보다 낮지 않으면 골키퍼로 처리합니다. 포지션 자료가 없으면 골키퍼라고 추측하지 않습니다.

골키퍼는 선택한 홈·원정·서드에 대응하는 **gk_home / gk_away / gk_third** 참조를 찾습니다. 다음처럼 명시적으로 골키퍼라고 구분된 매핑과 파일명을 지원합니다.

```xml
<record from="arsenal_keeper" to="graphics/pictures/team/602/kits/goalkeeper"/>
<record from="arsenal_keeper_away" to="graphics/pictures/team/602/kits/gk_away"/>
```

`goalkeeper`, `gk`, `gk_home`, `home_gk`, `gk1`은 골키퍼 홈으로, `gk2/gk3`은 원정/서드로 정규화합니다. XML 없이도 `602_gk_home.png`, `602_gk_away.png`, `602_goalkeeper.png`처럼 구분된 파일을 사용할 수 있습니다. 일반 `602.png`·홈 키트를 골키퍼에게 대신 사용하지 않습니다.

**키트팩에 해당 골키퍼 이미지가 없으면 2026/27 시즌 골키퍼 키트를 웹에서 찾고 합성합니다.** 일반 필드 선수용 키트로 대체하지 않습니다. 자동 생성을 잠시 멈추고 **유니폼 변경**에서 실제 골키퍼 유니폼 사진을 직접 선택할 수 있습니다. 고정 선택은 필드 선수용과 골키퍼용을 구분해 저장합니다. 골키퍼 키트가 나중에 추가되면 감시 중 자료 재점검에서 다시 처리합니다.

지원 이미지 형식은 PNG, JPG/JPEG, WebP, BMP입니다. 선택한 두 이미지만 PNG로 변환하여 Codex 작업 폴더에 복사합니다. 원본 팩의 이미지와 XML은 수정하지 않습니다. 명시적으로 지정한 얼굴 검색 폴더 안의 출력 페이스팩도 비교합니다. 작업 기록과 앱 팩의 백업 폴더는 원본 검색에서 제외합니다.

같은 구단·같은 home/away/third 키트 후보가 여러 개면 **작업마다 무작위 하나를 선택해 합성을 시작**합니다. 사용한 파일 경로는 대기열 작업 데이터의 `kit_reference`에 남습니다. 다른 유형의 키트를 대신 사용하지 않습니다. 같은 선수 ID에 얼굴이 여러 개 연결되는 경우에는 개별 얼굴 팩 폴더로 범위를 좁혀야 합니다.

특정 유니폼만 쓰고 싶을 때만 감시를 정지한 뒤, 선수를 선택하고 **유니폼 변경**에서 후보를 미리 본 후 **이 이미지 사용**을 누릅니다. 직접 파일도 선택할 수 있습니다. 기존 고정 선택은 계속 우선하며, **자동 검색으로 되돌리기**로 해제하면 무작위 선택으로 돌아갑니다. 고정 선택은 구단 ID와 유형별로 `config.json`의 `kit_overrides`에 저장됩니다.

키트 파일이 없으면 웹 검색을 시도합니다. 로컬 파일 손상·잘못된 설정은 합성 전 점검에서 해당 작업만 보류하고 다음 작업을 진행합니다. 감시 중에는 60초마다, 또는 세이브 변경 시 합성 전 자료 점검에서 보류된 작업을 다시 확인합니다. 실제 Codex 호출이 실패했거나 도구를 사용할 수 없는 경우, 중단된 호출은 자동 재호출하지 않습니다.

기존 XML에 일반 ID 매핑이 없고 `r-ID` 매핑이 있으면 그 근거를 사용해 생성선수 대상 경로를 유지합니다. XML이 없는 자료에서 `r-`가 필요한 경우에는 기존 ‘생성선수 r- 매핑 ID’ 설정을 사용할 수 있습니다. ID 크기만으로 생성선수 여부를 추측하지 않습니다.

## 커스텀 지시와 건조폼

**우측 상단 폴더 · 연결 → 공통 지시 펼치기**의 입력은 모든 다음 합성에 적용합니다. 예: `비 오는 경기장에서 골을 넣고 활짝 웃으며 오른손을 든 모습. 앞머리는 뒤로 넘겨주세요.` 기본 사진 스타일을 별도로 입력하지 않으며 프로그램의 기본 실사 스타일을 사용합니다. 원하는 외형·분위기는 공통 지시에 적으세요.

공통 지시는 자동 생성을 멈춘 뒤 **설정 저장**으로 반영합니다. 개별 지시는 **작업 대기열 → 작업 더블클릭**으로 입력합니다. 공통 지시와 개별 지시를 모두 전달하며 충돌하는 부분에서만 개별 지시를 우선합니다. 대기·보류·실패·중단 작업에서 영문 표시 이름과 지시를 저장할 수 있으며 자동 생성 중에도 가능합니다.

편집 창이 열려 있는 작업은 합성을 시작하지 않습니다. 저장·취소·닫기 후 처리를 재개하며 이미 합성 중인 요청은 변경할 수 없습니다. 다른 앱 인스턴스에서도 편집 잠금을 보호합니다. 앱이 종료된 뒤 남은 편집 잠금은 다음 자동 생성 시작 시 정리합니다.

개별 지시는 **선택한 작업에만** 적용되고 공통 지시보다 우선합니다. 다음 이적 작업에는 자동 복사하지 않습니다. 기존 버전에서 저장한 선수별 기본 지시는 호환성을 위해 유지하며, 새 작업별 지시가 있으면 우선합니다. 이미 저장된 이미지를 편집 창 저장만으로 재합성하지는 않습니다.

- 유효한 추가 지시가 없으면 원본 머리카락·표정·자세를 유지하라는 문구를 넣습니다.
- 공통 또는 선수별 추가 지시가 하나라도 있으면 위 유지 문구를 넣지 않습니다. 기본 사진 스타일보다 사용자 추가 지시를 우선합니다.
- 선수 얼굴 동일성은 기본으로 유지하도록 요청합니다.
- Codex는 사진 위에 이름·워터마크·테두리를 추가하지 않은 인물 원본 `portrait.png`를 생성합니다. 유니폼에 실제 인쇄된 구단 문장·제조사 로고·스폰서 글자는 참조에 맞춰 재현합니다. 프로그램이 로컬에서 최종 **350×350**으로 맞추고 하단에 정확한 이름을 그립니다. AI에게 선수 이름 철자를 그리도록 맡기지 않습니다.
- 기본 폼은 둥근 모서리·하단 어두운 그라데이션·가운데 정렬 이름을 가진 건조형 카드입니다. 참고 프로그램의 원본 템플릿 자산을 복제한 것은 아닙니다. 하단 이름은 라틴 문자 대문자로 표시하며 악센트 문자를 유지합니다. 긴 이름은 한 줄 안에 들어가도록 글꼴을 줄이며, 그래도 맞지 않으면 표시 이름 수정을 안내합니다.
- 추가 폼 템플릿 입력은 제거했습니다. 이 항목은 사진 위에 겹치는 투명 350×350 PNG 장식 파일을 뜻했으며, 이제 기본 건조폼만 자동 적용합니다. 예전 설정 파일의 템플릿 경로도 적용하지 않습니다.
- 기본 이름 글꼴은 `koverwatch.ttf`이며 TTF/OTF/TTC 파일을 별도로 선택할 수도 있습니다. 선택한 글꼴이 필요한 문자를 지원해야 합니다.

세이브의 통칭·전체 이름·법적 이름·이름+성에서 라틴 문자 이름을 우선 선택합니다. 한글 패치로 모든 이름이 한글인 경우에는 같은 Codex 합성 요청에서 영문/로마자 표기를 받습니다. 게임이 항상 별도 영문 필드를 제공하는 것은 아니며 로마자 표기가 공식 철자와 다를 수 있습니다. 선수별 영문 표시 이름으로 고정할 수 있습니다. `request.json`에는 `game_or_user` 또는 `codex_romanized` 출처도 남습니다.

작업 폴더의 `prompt.txt`와 `request.json`에 실제 적용한 지시와 표시 이름이 남습니다. 이미지 도구 호출 전에 이름·글꼴과 전용 페이스팩 폴더를 확인합니다.

### 이적 유형 선택

상단의 **포함할 이적 유형**에서 생성할 유형을 체크하고 **설정 저장**을 누르세요. **임대 이동**은 임대 이적과 임대 복귀를 함께 포함하며, 영입·방출은 **이동 방향**에서 선택합니다. 두 유형 중 하나만 켜 둔 기존 설정은 부분 선택으로 표시되며, 체크박스를 조작할 때까지 기존 선택을 유지합니다. 임대일 가능성이 있는 미확인 이동도 처리하지 않으려면 **유형 미확인**도 해제하세요. 기존 프리셋·구단별 방향·선수 개별 설정에 추가로 적용되며, 프리셋을 바꾸어도 유형 선택은 유지됩니다. 기본값은 세 항목 모두 선택입니다.

| 유형 | 판정 기준 |
| --- | --- |
| 완전 이적 | 확인된 비임대 소속·계약 변경. 자유계약 영입도 포함합니다. |
| 임대 이적 | 새 구단에서 임대 중임을 확인한 이동. 다른 구단으로의 재임대도 포함합니다. |
| 임대 복귀 | 이전 임대가 끝나고 확인된 원소속 구단으로 돌아온 이동입니다. |
| 유형 미확인 | 이전/현재 임대 상태·계약 정보가 부족하거나 서로 맞지 않아 구분할 수 없는 이동입니다. |

현재와 이전의 소속·임대 상태·계약 구단을 함께 비교합니다. 정보가 없을 때 완전 이적으로 추측하지 않습니다. 유형 도입 전 생성된 대기 작업은 과거 상태를 복원할 수 없으면 **유형 미확인**으로 표시합니다. 임대가 끝난 뒤 원소속이 아닌 다른 구단에 비임대 계약으로 들어간 경우는 완전 이적으로 구분합니다. 같은 구단에서 임대가 완전 이적으로 전환되어 소속이 그대로라면 새 작업을 만들지 않습니다.

유형 조건은 자동 이적 작업에 적용하며 선택한 선수도 이 조건을 따릅니다. **직접 생성**과 **현재 선수 생성 대기**는 이적 이벤트를 요구하지 않는 명시적 요청이므로 유형 조건을 적용하지 않습니다. 모두 해제하면 자동 이적 생성이 제외됩니다. 기존 대기·저장 대기 작업도 실행/적용 전 현재 조건을 다시 확인하며 이미 저장한 사진은 삭제하지 않습니다. 제외된 이동을 나중에 포함하도록 바꾸어도 과거 작업을 새로 만들지는 않습니다.

대기열의 **이적 유형** 열과 감지 진단에서 판정을 확인할 수 있습니다. 진단 보고서에는 분류 근거와 이전·현재 임대/계약 정보도 남깁니다. 유소년·1군 구분은 이번 변경에 포함하지 않습니다.

### 구단 직접 설정

1. **직접 설정**을 선택합니다. 세이브를 이미 읽었다면 구단 이름·ID로 검색합니다. 목록이 없으면 **구단 목록 불러오기**를 누르거나 ID를 직접 입력할 수 있습니다.
2. 구단을 선택하고 **영입된 선수만 / 방출된 선수만 / 방출·영입 모두** 중 하나를 고른 뒤 **추가 · 방향 변경**을 누릅니다.
3. 다른 구단도 추가하고 각 방향을 따로 지정합니다. 선택한 구단을 다시 선택하면 방향을 수정하거나 삭제할 수 있습니다.
4. **설정 저장**을 누릅니다. 이 동작 자체로 Codex를 호출하지 않습니다.

| 구단 설정 | 이동 | 생성 여부 |
| --- | --- | --- |
| 맨유 · 영입만 | 아스날 → 맨유 | 생성 |
| 맨유 · 영입만 | 맨유 → 아스날 | 제외 |
| 맨유 · 방출만 | 맨유 → 아스날 | 아스날을 선택하지 않아도 생성 |
| 맨유 · 모두 | 맨유 → 아스날 또는 아스날 → 맨유 | 둘 다 생성 |

영입은 **새 구단**, 방출은 **이전 구단**으로 판단합니다. 결과 유니폼은 항상 새 소속팀을 사용합니다. 무소속이 되면 새 유니폼 작업을 만들지 않지만, 이후 새 구단에 들어갈 때 이전 구단을 이어 비교합니다. 여러 조건에 맞아도 한 번의 이동에는 작업을 하나만 만듭니다.

직접 설정의 **내가 맡은 구단도 함께 포함**은 목록 밖의 내 구단을 추가합니다. 목록에 직접 지정한 구단은 그 구단의 개별 방향이 우선합니다. 구단 목록은 ‘직접 설정’ 모드에서만 적용되며 다른 프리셋과 숨겨진 합집합을 만들지 않습니다.

### 리그 참가 구단

프리미어리그·세리에 A·라리가·리그앙·분데스리가 참가 구단은 **해당 세이브의 현재 시즌 일정**으로 읽습니다. 대회 DB ID(11/32/67/16/22)를 세이브 내부 대회 키와 연결해 참가 구단을 구합니다. 현실의 고정 구단 명단을 쓰지 않아 세이브에서 승격·강등된 구단이 반영됩니다. 7월을 시즌 경계로 사용합니다.

리그 프리셋을 저장한 후 구단 목록 불러오기 또는 감시를 시작하면 추가 리더를 실행합니다. 해당 일정이 아직 생성되지 않았거나 리더가 지원하지 않는 경우 화면에 안내합니다. 미확인 리그 구단을 국가 전체나 현실 명단으로 대신 포함하지 않습니다. 구단 직접 설정은 리그 일정 읽기에 의존하지 않습니다. 실제 사용자 세이브에서 리그 리더의 호환성은 추가 확인이 필요합니다.

### 추가 조건과 호출 상한

**이적 감지 범위 → 설정 저장 아래 왼쪽의 고급설정** 버튼을 누르면 별도 팝업이 열립니다. 상단 탭에는 고급설정을 표시하지 않으며 시작 시에도 열지 않습니다. **창 닫기·X·Esc**로 닫고 같은 버튼으로 다시 열 수 있습니다. 닫았다 열어도 현재 편집 값은 유지하며, 파일에 반영하려면 **고급설정 저장**을 누르세요. **설정 저장**도 현재 편집한 전체 설정을 함께 저장합니다.

| 항목 | 기본값 |
| --- | --- |
| 지정·제외 선수 ID, 생성선수 매핑 ID | 빈칸 · 별도 지정 없음 |
| 최대 나이 | 전체 |
| 최근 24시간 호출 상한 | 제한 없음 |
| 같은 선수 재생성 간격 | 제한 없음 |
| 대기열 추가 후 생성 대기 | 대기 없음 |
| 감시 간격 | 세이브 업데이트 1회마다 |
| 처음 발견한 선수도 생성 | 끔 · 기준만 기록 |

제한 항목에 숫자를 입력하면 적용하며 0·빈칸은 제한 없음입니다. 기존 버전의 호출 상한 20회·재생성 24시간·생성 대기 30초가 모두 그대로인 설정은 새 기본값으로 전환합니다. 하나라도 별도로 조정한 묶음은 유지합니다. 이전 초 단위 감시 간격은 제거하고 저장 횟수 기본값 1회로 전환합니다.

- **선수 직접 설정**에서 이름으로 추가한 선수는 구단 범위에 더해 적용됩니다. **생성 제외**는 모든 선택보다 우선합니다.
- 최대 나이 0은 전체 나이입니다. 나이를 읽지 못한 선수는 나이 제한이 있을 때 제외합니다.
- 생성선수 여부를 ID 크기로 추측하지 않습니다. 기존 XML의 r- 매핑과 별도 지정한 생성선수 ID를 사용합니다.
- 호출 상한은 최근 24시간의 Codex 실행 시도 수이며 실패·재시도도 포함합니다. 상한과 재생성 간격에 걸린 작업은 대기 후 자동 진행합니다.
- 최초 읽기는 기본적으로 기준만 만듭니다. 범위를 늘려도 과거 이적을 소급 생성하지 않습니다. 현재 선수도 생성하려면 **이적 감지 범위 → 현재 선수 생성 대기**를 선택할 수 있으며 영입/현재 소속 조건에 맞는 선수만 추가됩니다.
- 같은 선수가 다시 이동하면 이전 미완료 작업을 대체합니다. 합성 중 새 소속으로 바뀌면 그 결과는 적용하지 않습니다.
- 자료 점검과 완성 이미지의 디스크·XML 저장은 감시 중 자동 재시도합니다. 실제 AI 호출의 실패·중단·도구 사용 불가는 확인 후 수동 재시도합니다.

### 저장 횟수에 따른 생성 간격

**감시 간격 · 세이브 업데이트 횟수**에 1 이상의 정수를 입력합니다. 1이면 매 업데이트마다, 2이면 두 번째 업데이트마다 누적 생성 작업을 처리합니다. 이적은 각 업데이트에서 기록하므로 첫 번째 업데이트의 방출도 두 번째 업데이트까지 유지됩니다. 그 사이 같은 선수가 다시 이동했다면 최신 소속의 작업만 남깁니다. 횟수가 차면 여러 대기 작업을 다음 저장 없이 이어 처리합니다.

최초 기준 읽기와 같은 파일의 반복 점검은 횟수에서 제외합니다. 횟수는 작업 폴더에 보관해 재시작 후 이어 세며, 간격 값을 변경하면 횟수를 0부터 다시 셉니다. 소속·선수 정보 읽기 자체는 Codex를 호출하지 않습니다. 이미 합성한 이미지의 저장 복구도 이 간격과 관계없이 진행합니다.

횟수는 프로그램이 확인한 완료된 파일 갱신 기준입니다. 앱을 끈 동안 또는 한 번의 합성이 진행되는 동안 같은 파일에 여러 번 덮어쓴 저장은 다음 확인에서 한 번으로 합쳐질 수 있습니다. 파일이 작성 중일 때는 완료를 기다리며 내부 파일 확인 주기는 사용자 설정으로 노출하지 않습니다.

## 직접 생성

이적을 기다리지 않고 **직접 생성 → 목록 불러오기 → 선수 선택 → 생성 요청**으로 한 명을 생성할 수 있습니다. 이미 목록을 읽었다면 이름·영문 이름·현재 구단·선수 ID로 바로 검색하세요. **유니폼 구단** 기본값은 선택한 선수의 현 소속팀이며, 다른 구단을 검색해 선택할 수 있습니다. **현 소속팀**으로 기본값에 돌아옵니다. 이 선택은 합성에 사용할 구단이며 실제 게임의 소속을 바꾸지 않습니다.

**참조 사진**은 선택 사항입니다. 왼쪽 위에서 선수를 선택한 뒤 아래의 **사진 불러오기**로 얼굴 참조를 넣으세요. 사진은 비율을 유지해 미리 보며 **제거**로 기존 자동 검색 방식에 돌아갑니다. 다른 선수로 바꾸면 이전 사진은 선택 해제됩니다. 선택한 사진은 해당 요청에만 적용하며 원본 파일을 변경하지 않습니다. 작업 기록에 보관한 PNG 사본이 Codex의 첫 번째 이미지인 `original.png`로 전달되고, 로컬 구단 키트가 있으면 두 번째 이미지로 전달됩니다. 키트가 없으면 같은 요청에서 웹으로 찾습니다. 이 사본이 손상되거나 사라지면 AI 호출 전에 보류하며 임의 웹 사진으로 대체하지 않습니다.

이 작업에만 적용할 지시는 선택 입력입니다. 공통 지시와 함께 전달하며 개별 지시가 우선합니다. 자동 이적 범위·제외 선수·나이 제한과 별개로 요청합니다. 호출 상한·재생성 간격은 유지하고 세이브 업데이트 횟수를 기다리지는 않습니다. 감시가 꺼져 있으면 요청한 작업만 처리하고, 자동 감시 중이면 대기열에 추가해 현재 합성 이후 차례로 처리합니다. 결과는 같은 저장 폴더에 `ID.png`와 config.xml 매핑으로 저장합니다.

같은 선수의 미완료 대기 요청은 새 요청으로 대체합니다. 생성·저장·개별 지시 편집 중인 작업은 완료한 뒤 다시 요청하세요. 선택 후 실제 소속·인물 정보가 바뀌면 다시 선택해야 하며, 생성 중 이적한 결과는 이전 소속의 작업과 같이 적용을 취소합니다.

## 중복 페이스팩 우선순위

**기존 페이스팩 폴더**에 여러 팩을 담은 상위 폴더를 지정할 수 있습니다. 같은 선수 ID의 매핑이 여러 팩에 있으면 `config.xml`이 있는 폴더의 상대 경로를 비교해 이름 순서상 뒤인 팩을 고릅니다. 예를 들어 `A_pack`과 `Z_pack`에서는 `Z_pack`을 선택합니다. 각 경로 단계는 대소문자 구분 없는 문자열 순서로 비교하며, 탐색기의 숫자 자연 정렬·사진 파일명·파일 수정일은 사용하지 않습니다. XML이 다른 하위 폴더의 사진을 가리켜도 XML 폴더가 기준입니다.

이 기준은 [FM26 그래픽 모딩 가이드](https://www.patreon.com/skogr/posts/how-to-fix-where-163716958)와 [FMAX의 FM27 그래픽 문서](https://hexase1-ship-it.github.io/fmle/en/graphics.html)에 설명된 후순 이름 팩 우선 규칙을 재현합니다. 예전 FM의 앞선 이름 팩 우선 안내와 다릅니다. 현재 플러그인은 게임이 선택한 사진 경로를 조회하지 않으므로 등록 경로 순서·캐시·게임 패치에 따른 모든 동작의 일치를 보장하는 기능은 아닙니다. 이번 변경은 실제 FM27 화면과의 대조가 필요합니다.

지정한 상위 폴더에 앱이 만든 팩이 있으면 선택 대상에 포함하고 `backups`와 작업 기록은 제외합니다. 자동 경로 찾기는 생성 팩을 새 원본 기본값으로 선택하지 않습니다. 우선순위가 높은 팩에 매핑만 있고 사진이 없으면 낮은 팩의 사진으로 임의 대체하지 않고 기존 사진 누락 처리로 넘깁니다. **같은 팩의 XML 안에서 같은 선수에게 서로 다른 사진을 중복 지정한 오류**는 계속 보류합니다.

XML 매핑이 전혀 없는 선수에 한해 ID 파일명 검색을 호환 기능으로 유지하며 이때도 뒤인 폴더를 우선합니다. XML 없이 사진만 복사해 둔 상태가 게임에 적용된다는 의미는 아닙니다. 선택한 원본 경로는 작업 데이터의 `portrait_reference`에 남고, Codex에는 그 사진을 `original.png`로 복사해 전달합니다. 유니폼 선택 방식·출력 ID 파일명·config.xml 저장은 유지합니다.

## 키트 파일이 없을 때

설정한 키트 폴더가 비어 있거나 존재하지 않는 경우, 해당 구단·유형의 이미지가 없는 경우, 이전 고정 선택 파일이 삭제된 경우에는 키트 누락만으로 멈추지 않고 Codex의 `--search`를 켭니다. 같은 요청에서 유니폼을 찾은 뒤 이미지 도구에 참조로 전달하도록 요청합니다. 웹에서 얼굴이나 키트 참조를 가져오는 요청은 Codex 작업 샌드박스의 네트워크 접근도 함께 허용하여 이미지 파일을 다운로드할 수 있게 합니다. 얼굴도 없으면 얼굴·키트를 함께 검색하며 별도 두 번째 AI 요청을 만들지 않습니다.

웹 키트의 시즌은 **2026/27(26/27)**로 고정합니다. 게임이 2028년 이후여도 바뀌지 않으며, 현재 최신 시즌·다른 시즌·미확정 콘셉트 디자인을 대체품으로 쓰지 않도록 요청합니다. 홈·원정·서드와 골키퍼 유형을 구분하고 구단·제조사의 공식 자료를 우선합니다. 다른 구단 유니폼을 지정한 직접 생성은 **요청한 유니폼 구단**으로 검색합니다.

Codex가 실제 참조 이미지 `kit.png`와 `kit-source.json`을 저장해야 합니다. 출처 파일에는 정확한 시즌 `2026/27`, 구단 ID, 유형, 확인한 구단명, HTTPS 원문·이미지 URL이 필요합니다. 시즌·구단·유형 불일치, 출처 누락, 손상된 이미지는 생성 완료로 적용하지 않습니다. 도구를 사용할 수 없거나 정확한 키트를 찾지 못하면 사유를 표시하며 유료 API나 다른 시즌으로 전환하지 않습니다. 실제 검색을 시작한 요청은 사용량이 발생할 수 있으며 실패한 AI 검색을 자동 반복하지 않습니다.

이미 있는 로컬 키트는 기존 선택 방식을 유지합니다. 로컬 파일은 시즌 메타데이터가 없어 앱이 실제 시즌을 판별하지 못하므로 **26/27 자료를 지정하세요.** 손상된 로컬 이미지나 잘못된 폴더 설정은 누락과 구분해 합성 전 점검에서 안내합니다. 검색 출처 기록과 파일 형식을 검사하는 기능이며 앱이 사진을 시각적으로 분석해 실제 시즌·로고 정확성까지 독립 검증하는 기능은 아닙니다.

다운로드한 키트와 출처는 작업별 폴더에 보관합니다. 후처리·저장 실패 후 재시작/재시도에서도 검증된 참조와 완성 원본을 재사용하며 추가 AI 호출을 하지 않습니다. 저장 직전에도 웹 키트 출처를 재확인합니다. 기존 로컬 팩의 파일이나 config.xml은 검색 참조를 수집하는 과정에서 수정하지 않습니다.

## 사진이 없는 선수

로컬 페이스팩에 선수 사진이 없으면 Codex의 `--search`를 켜고 선수 이름·영문 이름·생년월일·게임 소속을 참고해 실제 얼굴 사진을 찾도록 요청합니다. 선택한 유니폼 구단은 얼굴의 신원 확인 근거와 구분합니다. `original.png`와 HTTPS 출처를 기록한 `face-source.json`이 없으면 완료로 적용하지 않습니다. 기존 로컬 사진이 있으면 그 사진을 사용하며, 중복·손상된 사진을 사진 없음으로 취급하지 않습니다.

생성선수로 확인된 인물은 다른 실존 인물의 얼굴로 대체하지 않습니다. 웹 검색·사진 가져오기·이미지 참조 도구가 사용 불가하거나 신원을 확인할 수 없으면 보류하며 유료 API로 전환하지 않습니다. 검색 요청도 Codex 사용량이 발생할 수 있고, 보류한 AI 요청을 자동으로 반복하지 않습니다. 사진과 출처 파일의 형식은 확인하지만 사진 속 인물이 맞는지를 앱이 시각적으로 자동 판정하지는 않습니다. 실제 웹 검색과 생성의 성공 여부는 사용자의 Codex CLI 도구·권한에 따라 달라집니다.

## 작업 대기열

좌측 하단의 **전체 재시도**는 실패·보류·중단·후처리·저장 실패·저장 대기 작업을 다시 처리합니다. 완료된 작업을 일괄 재합성하지 않습니다. 단일 선택 방식이며 선택한 작업만 재시도하려면 우클릭 또는 작업 메뉴를 사용하세요. 유효한 합성 원본·완성 결과가 있으면 후처리와 저장만 재시도합니다. AI 호출 실패를 재시도하면 추가 사용량이 발생할 수 있습니다.

상단의 **현재 작업 중단**은 실행 중인 Codex 프로세스를 종료하고 자동 생성을 정지합니다. 다음 작업은 재시도나 시작 전까지 실행하지 않으며 완성된 파일은 보존합니다. 이미 제출한 요청의 사용량까지 취소하지는 못합니다. **작업 종료 후 멈춤**은 현재 합성이 끝날 때까지 기다린 뒤 정지합니다. 실행 상태는 최근 작업 메시지와 별도로 표시하며 오류를 일반 종료 메시지로 덮지 않습니다.

대기열의 모든 작업을 표시하고 주기적인 화면 갱신에서 선택·스크롤 위치를 유지합니다. 긴 설명은 선택 후 하단 설명 칸에서 줄바꿈과 내부 스크롤로 끝까지 읽거나 복사할 수 있습니다.

**⋯ 작업 메뉴** 또는 작업 우클릭에서 재시도·삭제·위로 이동·아래로 이동·맨 위로·유니폼 변경을 선택합니다. 대기·보류·실패·중단 작업은 드래그로도 순서를 바꿀 수 있습니다. 대상 행 위쪽에 놓으면 그 앞, 아래쪽에 놓으면 그 뒤로 이동하며 Escape로 취소합니다. 실제 생성 순서에 반영되고 재시작 후에도 유지되며 진행 중인 합성보다 앞서 끼어들지는 않습니다.

선택 작업의 **삭제** 또는 우측 하단의 **모든 대기열 삭제**는 작업을 목록에서 숨기고 이후 처리를 취소합니다. 생성·저장·편집 중인 작업은 유지합니다. 이미 저장한 사진·config.xml·호출 이력을 지우지 않으며 다음 작업 번호도 재사용하지 않습니다.

대기 작업을 **더블클릭**하면 개별 지시를, 결과가 있는 작업을 더블클릭하면 이미지를 엽니다. 유니폼 누락이나 시즌 선택이 필요하면 작업 메뉴의 **유니폼 변경**을 사용합니다. 중복 키트는 계속 무작위 선택합니다. **작업 기록 펼치기**로 상세 로그를 볼 수 있습니다.

**선수·구단 목록 불러오기 / 현재 선수 생성 대기**는 이적 감지 범위 탭에, **문제 진단 저장 / 선수 목록 저장 / 백업 복원**은 우측 상단 폴더 · 연결 창의 **문제 해결 펼치기** 안에 있습니다.

## 홈의 최근 생성 이미지

홈 오른쪽에는 **가장 최근 생성한 최대 5개**의 350×350 페이스온을 최신순으로 표시합니다. **이전·다음** 버튼으로 넘기며 `1 / 5` 형태로 현재 위치를 보여 줍니다. 이미지마다 선수 이름·새 소속팀·작업 번호·저장 상태를 표시합니다. 홈에는 페이지 전체 스크롤이 없으며 최근 이미지와 조작 버튼을 한 화면에 표시합니다.

생성이 끝나면 목록을 갱신하고, 재시작해도 작업 기록에서 최근 결과를 불러옵니다. 삭제되거나 손상된 결과 파일은 건너뜁니다. 이전 사진을 보고 있을 때 새 결과가 생겨도 그 사진이 최근 5개 안에 있으면 선택을 유지합니다. 범위를 벗어나면 최신 사진으로 돌아갑니다. 사진을 넘겨 보거나 기록을 불러오는 동작은 Codex를 호출하지 않습니다.

아래 통계에는 대기·생성 중·저장 완료 작업 수가 표시됩니다. 다른 세이브 파일로 바꾸어 설정을 저장하면 해당 세이브의 기록과 결과로 자동 전환합니다.

## 감지와 Codex 처리 방식

프로그램은 지정한 `.fm` 파일의 변경을 감시하고, 파일의 복사본을 읽습니다. 원본 세이브를 수정하지 않습니다. 매번 디스크 파일을 다시 파싱하지 않으며 변경 시에만 읽습니다. Codex가 합성하는 동안에도 주기적으로 세이브를 확인해 안정된 변경을 읽고 다음 이적을 대기열에 추가합니다. 단일 스레드에서 순서대로 처리하므로 큰 세이브를 읽는 동안에는 중단 반응이 늦어질 수 있습니다. 빠르게 연속 저장되어 중간 파일 상태를 읽지 못한 경우에는 마지막 저장을 기준으로 비교합니다. 다만 세이브를 읽을 때는 범위 밖 선수를 포함한 목록도 파싱하므로 큰 세이브에서는 메모리와 시간이 필요합니다.

소속은 기본적으로 세이브 리더의 등록 팀 구단(`club_uid`)으로 비교합니다. v0.4.2는 **등록 팀이 그대로인데 임대가 아닌 선수의 현재 계약 구단만 변경된 경우** 그 구단을 새 소속으로 사용하고 다음 저장에도 유지합니다. 등록 팀 자체가 바뀌면 등록 팀을 우선하며, 임대 중에는 계약 원소속 구단으로 유니폼을 바꾸지 않습니다. 계약 정보나 임대 여부가 불명확하면 임의로 계약 구단을 새 소속이라고 추측하지 않습니다.

새 버전의 최초 읽기에서는 등록 팀과 계약 구단이 다르다는 이유만으로 과거 이적을 만들지 않습니다. 기존 버전에서 계약 정보를 저장하지 않았던 경우도 첫 새 정보는 기준으로 보관합니다. 에디터 테스트는 **변경 전 저장을 읽은 뒤 → 에디터 이동 → 같은 파일 저장** 순서로 진행하세요. 이전 기록보다 과거 날짜의 세이브로 돌아가면 기존 기록을 보존하고 새 기준을 자동 설정합니다.

리더가 실제 게임의 임대·B팀·제휴 구단을 어떻게 해석하는지는 사용 중인 세이브와 대조 검증이 필요합니다. 두 저장 사이에 A → B → C로 이동했다면 마지막 C만 볼 수 있습니다. 자동저장이 여러 파일로 순환하면 지정한 파일이 갱신될 때 감지합니다.

### 신규 작업이 0개일 때

로그에서 다음 정보를 구분합니다. 지정한 선수 ID의 상세 정보는 최대 10명까지 표시합니다.

- 최초 기준 기록인지, 이전 저장과 비교한 결과인지
- 실제 소속 변화 수, 생성 범위에서 제외한 수, 추가한 작업 수
- 지정 선수의 이전 → 현재 소속, 등록 팀 구단 ID와 현재 계약 구단 ID
- 구단/선수 범위 밖, 제외 ID, 나이 제한, 무소속 등 생성 제외 사유
- 지정한 선수 ID를 세이브에서 찾지 못한 경우

예를 들어 맨유의 ‘영입된 선수만’을 선택한 상태에서 선수가 아스날로 나가면 범위 밖입니다. 맨유의 ‘방출된 선수만’ 또는 ‘방출·영입 모두’를 선택하면 아스날을 따로 선택하지 않아도 생성합니다.

최근 진단은 작업 폴더의 `latest_detection.json`에 자동 저장합니다. **우측 상단 폴더 · 연결 → 문제 해결 펼치기 → 문제 진단 저장**로 같은 JSON을 내보낼 수도 있습니다. 아직 진단이 없다면 **이적 감지 범위 → 선수 목록 불러오기**을 누르거나 자동 감시의 첫 점검을 기다리세요. 파일에는 감시 세이브 경로, 게임 날짜, 지정 선수 및 소속 변경 일부의 비교 정보가 포함됩니다. 전체 세이브를 내보내거나 Codex를 호출하지 않습니다.

작업별 폴더에 로컬 사진이 있으면 `original.png`, 유니폼 `kit.png`, `prompt.txt`, 결과 스키마를 준비하고 `codex exec`를 호출합니다. 얼굴 또는 키트가 없으면 `--search`를 추가하고 현재 있는 이미지만 첨부합니다. 두 참조가 모두 없으면 이미지 첨부 없이 검색을 요청합니다. Codex가 얼굴 사진·출처 및 2026/27 키트·출처를 확보하도록 요청합니다. 이미지 도구를 사용할 수 없으면 보류합니다. 유료 API로 자동 전환하거나 별도 이미지 서비스를 자동 가입하지 않습니다. 계정의 실제 사용 한도·제공 기능은 사용 환경에 따라 확인해야 합니다.

Codex에는 원본 얼굴(있을 때)·유니폼 참조와 선수·영문 이름·생년월일·구단 이름을 전달합니다. 전체 세이브는 프롬프트에 넣지 않습니다. 작업은 `workspace-write` 샌드박스에서 실행하며 승인 우회 플래그는 사용하지 않습니다. 비대화 실행의 승인 요청은 허용하지 않아 권한이 필요한 동작은 실패할 수 있습니다. 사용자의 Codex 설정·신뢰된 MCP 구성도 실제 동작에 영향을 줄 수 있습니다.

AI 원본은 350~4096px 정사각 PNG로 받고, 최종 결과는 **정확히 350×350 PNG**로 검증합니다. 로컬 이름 렌더링 기록도 확인합니다. 얼굴 동일성이나 유니폼 정확성을 자동 판정하지는 않습니다.

## 이름 폰트와 코너 모양

사용자가 제공한 원본 세 파일을 프로그램의 `fonts/` 폴더에 포함합니다.

| 폰트 | 파일 | 기본값 |
| --- | --- | --- |
| Koverwatch Regular | `fonts/koverwatch.ttf` | 기본 선택 |
| Bebas Neue Regular | `fonts/BebasNeue.otf` | 선택 가능 |
| Venus Rising Regular | `fonts/venus rising rg.ttf` | 선택 가능 |

**폴더 · 연결 → 이름 글꼴**의 드롭다운에서 선택하고 **설정 저장**을 누르세요. **기본값으로 초기화**는 포함된 Koverwatch·연한 금색·30px·굵게 켜짐으로 이름 스타일을 되돌립니다. 폰트를 PC에 설치하거나 다른 위치에 복사할 필요가 없습니다. 설정 파일을 다른 폴더에 두어도 프로그램에 포함된 기본 폰트를 읽습니다. Windows EXE 빌드 스크립트에도 `fonts/` 포함 옵션을 추가했으며 실제 Windows 빌드는 이 환경에서 검증하지 않았습니다.

**폰트 불러오기**에서는 포함 폰트 폴더를 열어 주며 다른 **TTF·OTF·TTC** 파일을 직접 선택할 수도 있습니다. 외부 파일을 선택했다면 해당 위치에 계속 보관하세요. TTC는 첫 번째 글꼴을 사용하며 이름 길이에 맞춰 글꼴 크기를 자동 조정합니다.

이전 버전의 미설정 또는 알려진 시스템 기본 폰트(맑은 고딕·Noto Sans CJK 등) 설정은 포함된 `koverwatch.ttf`로 전환합니다. v0.7.0의 설정 파일 옆 기본 경로에 파일이 없을 때도 포함 폰트로 옮깁니다. 기존 사용자 지정 폰트와 실제 존재하는 이전 Koverwatch 파일은 유지합니다. 전환 후 직접 지정한 선택은 다음 실행에도 유지합니다. 시스템 폰트를 자동 검색하거나 대체하지 않습니다.

폰트 파일을 삭제했거나 경로가 잘못되면 **합성은 Codex 호출 전에 보류**합니다. 포함 파일은 저장소를 다시 내려받아 복구하거나 다른 폰트를 선택하세요. 손상된 폰트도 설정 저장 또는 합성 전 검사에서 안내합니다. 세 사용자 제공 파일을 모두 실제로 읽고 350×350 이름 렌더링을 검증했습니다.

최종 이미지는 네 모서리 모두 **60px 반경**이며 가장자리를 부드러운 투명도로 처리합니다. 폰트와 새 모서리는 이후 생성되는 결과부터 반영합니다. 기존 PNG나 저장 재시도용 완성 결과를 자동으로 다시 만들지는 않습니다.

## 페이스팩 적용과 복구

게임에서 사용하는 그래픽 폴더 안의 기존 페이스팩 또는 새 폴더를 **페이스팩 저장 폴더**로 선택하세요. **처음에도 비어 있을 필요가 없습니다.** 원본 얼굴 폴더와 같은 곳으로 지정할 수도 있습니다. 이전 작업 폴더에서 사용하던 출력 폴더도 재사용할 수 있습니다.

최종 PNG는 **선수ID.png**로 저장하고 같은 선수의 다음 결과는 해당 파일을 교체합니다. `config.xml`의 해당 선수 초상화 from도 동일한 ID로 갱신합니다. 기존 팩의 임의 파일명·하위 경로·다른 선수·키트 등 다른 매핑과 XML 속성은 보존합니다. 일반 ID는 `graphics/pictures/person/ID/portrait`, 지정된 생성선수는 `graphics/pictures/person/r-ID/portrait`로 매핑합니다. 이 규칙의 FM27 스킨별 동작은 실제 게임에서 확인해야 합니다.

**매 작업의 성공 조건은 PNG와 config.xml 저장이 모두 끝나는 것**입니다. 실패했거나 합성 중 다시 이적한 이미지는 매핑에 추가하지 않습니다. 기존 선수 매핑은 보존하고 동일 선수만 최신 파일로 바꿉니다. XML은 백업 후 임시 파일을 완성하여 교체합니다.

정상 합성 원본과 성공 응답을 확인하면 먼저 복구 정보를 저장한 뒤 이름 렌더링·PNG·XML 저장을 처리합니다. 이 로컬 단계가 실패하면 **후처리·저장 실패** 상태로 원본을 보관합니다. 감시 중에는 60초마다 추가 AI 호출 없이 후처리·저장을 재시도합니다. 즉시 처리하려면 작업 우클릭의 **재시도**를 사용하세요. 앱 재시작 후에도 유효한 원본을 재사용합니다. AI가 실패했거나 완성 원본이 없는 중단 요청은 수동 재시도 때 Codex를 다시 호출할 수 있습니다. 합성 지시나 유니폼 선택이 달라진 원본은 재사용하지 않으며, 합성 도중 다시 이적한 결과도 자동 적용하지 않습니다.

XML을 바꾸기 전에 `backups/`에 원본 XML과 교체할 대상 ID 이미지, 복구 정보를 저장합니다. 기존 팩 전체의 이미지를 매 작업마다 복사하지는 않습니다. **우측 상단 폴더 · 연결 → 문제 해결 펼치기 → 백업 복원**으로 선택한 작업의 대상 선수 매핑·이미지를 복구하며, 그 뒤에 처리한 다른 선수는 유지합니다. 원래 다른 파일명의 사진에 연결되어 있었다면 그 연결로 되돌리고 해당 원본 사진은 건드리지 않습니다. XML 저장 실패 시 교체했던 ID 이미지도 원복하고 생성 결과는 재시도용으로 보관합니다.

저장 폴더의 다음 항목은 FM 표시용이 아닌 앱의 관리 자료입니다.

| 항목 | 역할 |
| --- | --- |
| `.fm-face-lock/` | 같은 페이스팩에 여러 작업이 동시에 PNG·XML을 쓰지 않도록 OS 잠금을 거는 위치. 작업이 끝나도 잠금 파일은 남지만 실제 잠금은 해제됩니다. |
| `backups/` | 변경 전 XML·대상 선수 이미지·복구 정보를 보관. 삭제하면 해당 변경 전 상태로 복구할 수 없습니다. |
| `.fm-face-shared` | 기존 파일 또는 다른 작업 폴더의 결과가 섞인 팩이라는 표시. 원본 이미지 검색에서 해당 팩을 제외하지 않고, 앱 전용 팩에만 허용하는 일괄 파일명 변환을 막는 데 씁니다. |

앱에서 계속 쓰는 폴더라면 위 항목을 유지하세요. 잠금 폴더나 공유 표시를 임의로 지우면 동시 저장 보호나 폴더 분류에 영향을 줄 수 있습니다. 이미지와 매핑의 게임 적용 자체는 선수 PNG와 `config.xml`이 담당합니다.

손상된 XML이나 DTD/엔티티, ID 이미지가 다른 대상 매핑에도 공유된 경우에는 파일을 임의로 덮어쓰지 않고 보류합니다. 같은 저장 폴더를 여러 작업 폴더가 사용할 때에는 폴더 잠금으로 동시 갱신을 막고 자동 저장 재시도로 이어갑니다.

v0.3.3 이하의 `ID_작업번호.png`는 감시 시작 시 재합성 없이 `ID.png`와 대응 XML로 변환합니다. 기존 파일은 `backups/legacy/`로 옮깁니다. 이전 버전의 XML만 있는 백업도 해당 파일을 사용해 복구할 수 있습니다. 다른 페이스팩에서 같은 ID를 매핑하는 충돌이나 게임의 로딩 순서까지 자동 해결하지는 않습니다. 파일 저장 완료와 게임 화면의 반영은 별개입니다. 기본 설정은 게임 내부 그래픽 새로고침을 호출하지 않습니다. v0.10.0의 별도 실험 플러그인을 설치하고 옵션을 켜는 경우에만 새로고침을 요청합니다. [DF11의 설치 안내](https://www.df11faces.com/post/df11-megapack-lite-instructions)는 FM26·FM27의 스킨 새로고침 버튼 부재와 게임 완전 재시작을 안내합니다. 생성이 여러 개라면 묶어서 완료한 뒤 게임을 완전히 종료하고 다시 실행하세요. 새 게임을 시작할 필요는 없습니다.

**작업 폴더는 직접 설정하지 않습니다.** 연결할 세이브 파일을 선택하고 설정을 저장하거나 자동 생성을 시작하면 세이브 경로별로 기록을 자동 선택합니다. 새 기록은 설정 파일 옆의 `workspaces/`에 만들고 경로 연결은 `config.json`에 보관합니다. 같은 세이브로 돌아오면 그 파일의 기록을 이어 씁니다.

기존 설치에서 사용하던 작업 폴더의 DB가 현재 세이브와 연결되어 있으면 그대로 연결하므로 기준·대기열·최근 결과를 잃지 않습니다. 저장 날짜가 이전 기록보다 과거라면 기존 기록을 보존한 별도 작업 폴더를 만들고 기준만 새로 기록합니다. 이 경우 기존 페이스팩 이미지를 과거 상태로 자동 복원하지는 않습니다.

같은 파일명·같은 날짜 또는 이후 날짜로 완전히 다른 커리어를 덮어쓰면 완벽히 구분할 수 없습니다. 다른 커리어는 별도 세이브 파일명을 사용하세요. 페이스팩 저장 위치는 재사용할 수 있으며 같은 선수 ID는 마지막으로 저장한 결과가 됩니다.

## 실제 게임 없이 감지 확인

`examples/before.json`을 별도의 `current.json`으로 복사하고 앱의 입력으로 지정합니다. 최초 읽기 뒤 `examples/after.json` 내용으로 **같은 current.json 파일**을 바꾼 다음 다시 읽으세요. Demo Player의 Club A → Club B 변경이 대기열에 1개 나타납니다. 원본 이미지와 Codex가 없으므로 합성 검증 예시는 아닙니다.

기존 JSON 형식이 아닌 임의 CSV·HTML 파일은 자동으로 해석하지 않습니다. 예시 JSON은 FM 세이브 어댑터와 같은 내부 형식입니다.

## 전 구단 팀 종류 조회 경로 진단

사용자가 제공한 FM27 `27.1.0+2505117`, 게임 날짜 `2028-07-07`의 맨유 비교에서는 두 선수 모두 1군 `team_id=540 / slot=0`, U21 `28346 / 1`, U18 `28347 / 2`로 바뀌었습니다. 계약 팀 ID는 세 상태 모두 `540`입니다. 등록 팀 ID가 실제 배정 변경을 담는다는 것은 확인했지만 다른 구단에도 동일한 슬롯 의미를 적용하지 않습니다. 슬롯 3이나 다른 미검증 팀은 이름을 추측하지 않습니다.

다음은 게임이 제공하는 실제 팀 종류 정보의 조회 경로를 조사하는 단계입니다.

1. 앱 저장소를 업데이트한 뒤 **export_team_metadata.bat**를 실행합니다. FM27 실행·재시작·선수 이동·기존 플러그인 재설치는 필요 없습니다.
2. 설치 경로가 하나로 확인되면 자동 진행합니다. 찾지 못했거나 여러 개면 FM27 설치 폴더의 **fm.exe**를 선택합니다. BepInEx interop가 이미 생성되어 있어야 합니다.
3. 완료 후 열린 `diagnostics` 폴더의 **team-metadata.json**만 대화에 첨부합니다. 기존 `squad-diagnostic.json`과 다른 파일입니다.

```powershell
.\export_team_metadata.bat
```

Windows x64 실행 파일과 자체 런타임이 저장소에 포함되어 있어 사용자의 .NET 설치는 필요 없습니다. 도구는 게임 DLL을 로드하지 않고 정적 메타데이터만 읽습니다. 게임 메서드·getter·생성자·AI를 호출하거나 세이브·페이스팩·게임 파일을 변경하지 않습니다. 보고서는 전송 한도보다 작은 24MiB 이내이며 전체 DLL·선수 목록·계정 정보·설치 경로·문자열 상수·메모리 주소를 포함하지 않습니다. 부분 읽기 오류와 목록 제한은 보고서에 표시합니다.

실제 게임 DLL은 사용자 PC에만 있으므로 이 보고서를 받아야 팀 종류 API의 존재와 형식을 조사할 수 있습니다. 형식·enum 이름을 찾았다는 사실만으로 전 구단의 실제 값이나 동작이 검증되는 것은 아닙니다. 결과에 따라 읽기 전용 런타임 검증이 추가로 필요할 수 있습니다. 유소년·1군 필터는 정확한 조회와 연결이 검증된 뒤 구현합니다.

## 개발과 출처

```console
python -m unittest discover -s tests -v
python app.py --config config.json --scan
```

세이브 읽기는 [fmsave](https://github.com/rhiever/fmsave)의 공개 Python 라이브러리를 사용합니다(MIT, 0.12.6 고정). 라이브러리 문서상 FM27 `27.0.0+2486695`가 전체 리더 등록 대상이며, 0.12.6에는 `27.1.0+2505117`의 구단 레이아웃 수정이 포함되었습니다. 후자는 모든 리더가 등록된 빌드가 아니므로 `known_build`가 false일 수 있습니다. 이 앱은 필요한 선수·구단 읽기에 한해 해당 빌드를 명시적으로 허용하고 엄격 무결성 검사 실패는 중단합니다. 다른 미등록 빌드는 계속 거부합니다. 알려진 빌드 또는 호환 대상으로 지정됐다는 사실이 모든 필드의 게임 대조 검증을 의미하지는 않습니다.

Codex 연결은 [공식 비대화 실행 문서](https://developers.openai.com/codex/noninteractive/)와 설치된 CLI의 도움말을 기준으로 작성했습니다. 이미지 검증에는 Pillow를 사용합니다. 의존성 코드는 이 소스 압축에 복제하지 않고 설치 시 공식 패키지 저장소에서 받습니다.

커뮤니티가 만든 비공식 프로그램이며 Sports Interactive 또는 SEGA의 공식 제품이 아닙니다.
