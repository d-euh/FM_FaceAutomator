# FM Face Automator · v0.7.0 미리보기

FM Newgen Face Studio와 연결하지 않는 독립형 데스크톱 프로그램입니다. Windows 10용 실행 배치파일과 Python 소스를 제공합니다. 이 배포물에는 미리 빌드한 Windows EXE가 없습니다.

범위를 지정하고 **범위 저장** 후 홈에서 **감시·생성 시작**을 누르면 **세이브 저장 → 이적 감지 → 이미지 자료 선택 → Codex 합성 → 선수 ID 파일명·350×350·하단 영문 이름 → config.xml 갱신**까지 자동 진행합니다. 최초 읽기는 기준만 기록합니다. 현재 선수들을 일괄 생성하려면 대기열의 ‘현재 범위도 생성 대기’를 선택할 수 있습니다.

v0.4.0은 경로 자동 입력, 중복 키트 무작위 선택, ID 파일명, 영문 이름과 자동 복구를 추가했습니다. v0.3.3 사용자는 앱을 닫고 `git pull --ff-only` 후 `start_windows.bat`로 시작하면 됩니다. 의존성 재설치는 필요 없습니다. 앱 환경 설정은 `config.json`, FM 이미지 매핑은 `config.xml`입니다.

v0.4.1부터 기존 파일이 있는 페이스팩을 **페이스팩 저장 폴더**로 바로 지정할 수 있습니다. 원본 얼굴 폴더와 같은 경로도 지원합니다. 생성한 선수의 파일·매핑만 백업 후 갱신하고 나머지는 보존합니다.

v0.5.0은 **홈의 최근 생성 이미지·작업 통계**, 별도의 **생성 범위** 탭, 리그 프리셋과 구단별 영입·방출 방향을 추가합니다. 기존 설정은 기존 방향을 유지해 옮깁니다. 새 설정은 내 구단의 영입·방출 모두가 기본값입니다. 의존성 추가 없이 `git pull --ff-only` 후 다시 실행하면 됩니다.

v0.5.2는 실버그레이 배경(`#D6D7DB`), 밝은 카드(`#F5F5F7`), 짙은 회색 본문(`#28252F`)과 중간 회색 설명을 사용합니다. v0.5.3에서는 모든 동작 버튼을 보라(`#710A9E`, RGB 113/10/158) 배경과 흰 글자로 통일합니다. 선택한 프리셋은 체크 표시로 구분합니다. 선택된 탭·통계 숫자·입력 포커스에도 보라를 사용합니다. Linux 화면에서 홈과 생성 범위의 색상 구분을 확인했습니다. 추가 설치 없이 저장소를 업데이트한 뒤 앱을 다시 실행하면 적용됩니다.

v0.6.0은 추가 조건·호출량을 별도 **고급설정** 탭으로 옮깁니다. 생성 범위의 **범위 저장 아래 왼쪽**에 있는 버튼으로 열 수 있습니다. 기본값은 추가 제한 없음이며, 감시 간격은 초 대신 **세이브 업데이트 1회마다**입니다. 의존성 재설치 없이 앱을 닫고 `git pull --ff-only` 후 다시 실행하세요.

v0.6.1은 이름 폰트 선택·검증과 기본 글꼴 복귀를 보강하고, 새 결과의 코너 반경을 **60px**로 변경합니다. 350×350 크기와 영문 하단 이름을 유지하며 둥근 부분에 글자가 잘리지 않도록 좌우 여백을 맞춥니다.

v0.7.0은 고급설정을 생성 범위의 버튼으로만 열 수 있는 **팝업창**으로 바꾸고, 이름 폰트를 시스템 자동 검색 대신 **koverwatch.ttf**로 고정합니다. 폰트 선택 위치는 **폴더 · 연결**이며 다른 폰트를 직접 선택할 수도 있습니다. 폰트 파일 자체는 저장소에 포함되어 있지 않습니다.

## 실행

v0.5.4에서 **감지 진단 저장**은 **작업 대기열 상단의 ‘현재 작업 후 정지’ 오른쪽**에 있습니다. 창 높이가 부족하면 목록 높이가 줄어들고 하단 버튼 공간을 유지합니다. Linux 화면에서 버튼 표시와 JSON 내보내기를 확인했습니다.

1. [python.org](https://www.python.org/downloads/windows/)에서 Python 3.12 이상을 설치합니다. Tk와 Python Launcher를 포함하세요.
2. 저장소를 내려받고 `setup_windows.bat`를 실행합니다. 전용 `.venv`에 세이브 읽기 및 이미지 검증 라이브러리를 설치합니다.
3. [Codex CLI](https://developers.openai.com/codex/cli/)를 설치하고 해당 PC에서 로그인을 완료합니다. 사용 계정과 CLI 환경에서 이미지 생성 도구를 사용할 수 있어야 합니다.
4. `start_windows.bat`를 실행합니다. 최초 실행 시 `config.json`이 만들어집니다.
5. 자동 입력한 세이브·얼굴·키트·출력·Codex 경로를 확인합니다. 찾지 못했거나 다른 위치를 쓰려는 항목만 직접 바꾸세요. 일반적 위치 밖에 자료가 있으면 **FM 자료 상위 폴더**를 지정하면 됩니다.
6. 생성 범위를 지정하고 **범위 저장** 후 홈에서 **감시·생성 시작**을 누릅니다. 감시 중에는 창을 열어 두세요. 프로그램을 다시 실행하면 감시 시작을 한 번 누릅니다.

`build_windows.bat`는 Windows에서 EXE 묶음을 만드는 선택 기능입니다. PyInstaller를 설치하고 `dist\FMFaceAutomator\`에 생성합니다. 빌드 스크립트는 이 Linux 환경에서 실행 검증하지 않았습니다. 배포할 때는 EXE 하나가 아닌 생성된 폴더 전체를 사용하세요.

## 자동 경로 입력

앱이 열리면 별도 검색 버튼이나 확인 팝업 없이 다음 위치를 읽고 미설정 항목의 기본값을 채웁니다. 세이브·자료 상위 폴더를 직접 지정한 뒤에도 자동 확인합니다.

- Windows 문서 폴더 등록 위치 및 OneDrive의 Sports Interactive/Football Manager 27 또는 Football Manager 2027
- 해당 게임의 games 폴더에서 가장 최근 수정된 `.fm` 세이브 (세이브를 아직 지정하지 않았을 때)
- 선택한 세이브의 games 옆 graphics, 현재 얼굴·키트 폴더, FM 자료 상위 폴더
- PATH와 Windows npm 설치 경로의 실제 `codex.exe`

얼굴 폴더 후보가 여러 개면 매핑이 가장 많은 팩을 기본값으로 사용합니다. 키트는 여러 리그·팩을 함께 검색하도록 공통 상위 폴더를 사용합니다. 숫자 파일명만 있는 자료는 얼굴/키트 종류를 확정할 수 없어 직접 지정할 수 있습니다. 출력 기본값은 발견한 graphics 아래 `000_FMFaceAutomator`입니다. 이전에 직접 지정해 저장한 경로와 검색 중 사용자가 수정한 값은 덮어쓰지 않습니다.

자동 검색은 드라이브 전체를 읽지 않습니다. 발견할 수 없는 항목만 직접 입력하거나 옆의 **선택**으로 지정하세요. 원본 얼굴·키트 자료는 사용자가 보유한 파일을 사용하며 자동 다운로드하지 않습니다. Windows의 `.cmd`/`.bat`는 Codex 실행 대상으로 받지 않습니다.

## 원본 얼굴·유니폼 자료

기존 매핑에서 인식하는 형태는 다음과 같습니다. XML의 `from` 값을 파일명으로 사용하므로 사진 파일명이 선수 ID나 구단 ID일 필요는 없습니다.

```xml
<record from="photos/player_photo" to="graphics/pictures/person/900001/portrait"/>
<record from="photos/newgen_photo" to="graphics/pictures/person/r-900002/portrait"/>
<record from="manchester_h" to="graphics/pictures/team/20/kits/home"/>
```

유니폼 유형은 설정의 **home / away / third**에서 고릅니다. 3D `kit_textures` 매핑은 2D 유니폼 참조와 구분하여 검색 결과에서 제외합니다. 2D 이미지나 실제 유니폼 사진을 참조로 사용할 수 있지만, 로고만 있는 폴더나 게임 기본 압축 리소스를 자동으로 유니폼 사진으로 바꾸지는 않습니다.

지원 이미지 형식은 PNG, JPG/JPEG, WebP, BMP입니다. 선택한 두 이미지만 PNG로 변환하여 Codex 작업 폴더에 복사합니다. 원본 팩의 이미지와 XML은 수정하지 않습니다. 출력 페이스팩과 작업 폴더는 원본 검색에서 제외합니다.

같은 구단·같은 home/away/third 키트 후보가 여러 개면 **작업마다 무작위 하나를 선택해 합성을 시작**합니다. 사용한 파일 경로는 대기열 작업 데이터의 `kit_reference`에 남습니다. 다른 유형의 키트를 대신 사용하지 않습니다. 같은 선수 ID에 얼굴이 여러 개 연결되는 경우에는 개별 얼굴 팩 폴더로 범위를 좁혀야 합니다.

특정 유니폼만 쓰고 싶을 때만 감시를 정지한 뒤, 선수를 선택하고 **유니폼 이미지 선택**에서 후보를 미리 본 후 **이 이미지 사용**을 누릅니다. 직접 파일도 선택할 수 있습니다. 기존 고정 선택은 계속 우선하며, **자동 검색으로 되돌리기**로 해제하면 무작위 선택으로 돌아갑니다. 고정 선택은 구단 ID와 유형별로 `config.json`의 `kit_overrides`에 저장됩니다.

파일이 없거나 손상되면 해당 작업만 보류하고 다음 대기 작업을 진행합니다. 감시 중에는 60초마다, 또는 세이브 변경 시 합성 전 자료 점검에서 보류된 작업을 다시 확인합니다. 실제 Codex 호출이 실패했거나 도구를 사용할 수 없는 경우, 중단된 호출은 자동 재호출하지 않습니다.

기존 XML에 일반 ID 매핑이 없고 `r-ID` 매핑이 있으면 그 근거를 사용해 생성선수 대상 경로를 유지합니다. XML이 없는 자료에서 `r-`가 필요한 경우에는 기존 ‘생성선수 r- 매핑 ID’ 설정을 사용할 수 있습니다. ID 크기만으로 생성선수 여부를 추측하지 않습니다.

## 추가 지시와 건조폼

‘추가 지시 · 건조폼’ 탭의 공통 지시는 모든 다음 합성에 적용합니다. 예: `비 오는 경기장에서 골을 넣고 활짝 웃으며 오른손을 든 모습. 앞머리는 뒤로 넘겨주세요.`

대기열의 선수를 선택하고 **선수별 이름·지시**를 누르면 하단 표시 이름과 그 선수의 추가 지시를 따로 저장할 수 있습니다. 공통 지시와 선수별 지시는 함께 전달하며, 충돌하면 선수별 지시를 우선합니다. 해당 ID가 다른 인물에게 재사용된 경우 이전 인물의 지시는 적용하지 않습니다. 변경은 다음 합성부터 반영되며 이미 저장된 이미지를 자동으로 다시 합성하지는 않습니다.

- 유효한 추가 지시가 없으면 원본 머리카락·표정·자세를 유지하라는 문구를 넣습니다.
- 공통 또는 선수별 추가 지시가 하나라도 있으면 위 유지 문구를 넣지 않습니다. 기본 사진 스타일보다 사용자 추가 지시를 우선합니다.
- 선수 얼굴 동일성은 기본으로 유지하도록 요청합니다.
- Codex는 글자나 테두리 없는 인물 원본 `portrait.png`를 생성합니다. 프로그램이 로컬에서 최종 **350×350**으로 맞추고 하단에 정확한 이름을 그립니다. AI에게 선수 이름 철자를 그리도록 맡기지 않습니다.
- 기본 폼은 둥근 모서리·하단 어두운 그라데이션·가운데 정렬 이름을 가진 건조형 카드입니다. 참고 프로그램의 원본 템플릿 자산을 복제한 것은 아닙니다. 하단 이름은 라틴 문자 대문자로 표시하며 악센트 문자를 유지합니다. 긴 이름은 글꼴을 줄이거나 두 줄로 배치하며, 그래도 맞지 않으면 표시 이름 수정을 안내합니다.
- 정확한 별도 폼이 있으면 **투명도를 포함한 350×350 PNG 템플릿**을 선택할 수 있습니다. 이름은 템플릿 위에 그립니다. 템플릿에는 이름이 미리 그려져 있지 않은 것이 적합합니다.
- 기본 이름 글꼴은 `koverwatch.ttf`이며 TTF/OTF/TTC 파일을 별도로 선택할 수도 있습니다. 선택한 글꼴이 필요한 문자를 지원해야 합니다.

세이브의 통칭·전체 이름·법적 이름·이름+성에서 라틴 문자 이름을 우선 선택합니다. 한글 패치로 모든 이름이 한글인 경우에는 같은 Codex 합성 요청에서 영문/로마자 표기를 받습니다. 게임이 항상 별도 영문 필드를 제공하는 것은 아니며 로마자 표기가 공식 철자와 다를 수 있습니다. 선수별 영문 표시 이름으로 고정할 수 있습니다. `request.json`에는 `game_or_user` 또는 `codex_romanized` 출처도 남습니다.

작업 폴더의 `prompt.txt`와 `request.json`에 실제 적용한 지시와 표시 이름이 남습니다. 이미지 도구 호출 전에 이름·글꼴·템플릿과 전용 페이스팩 폴더를 확인합니다.

## 생성 범위와 호출량

홈의 **생성 범위 설정 →** 또는 상단 **생성 범위** 탭에서 지정합니다. **범위 저장** 후 홈의 **감시·생성 시작**으로 실행합니다. 실행 중 범위를 바꾸려면 현재 작업 후 정지하고 저장한 뒤 감시를 다시 시작하세요. 각 화면의 상단 **홈**으로 돌아갈 수 있습니다.

### 원클릭 범위

- 내가 맡은 구단만 (새 설정 기본값)
- 모든 이적
- 5대 리그만
- 프리미어리그만
- 프리미어리그 빅6만 (아스날·첼시·리버풀·맨시티·맨유·토트넘)
- 세리에 A만
- 라리가만
- 리그앙만
- 분데스리가만

새 설정의 이동 방향 기본값은 **방출·영입 모두**이며 **영입된 선수만 / 방출된 선수만**으로 바꿀 수 있습니다. 기존 버전에서 옮긴 설정은 종전의 영입 기준을 유지합니다.

### 구단 직접 설정

1. **직접 설정**을 선택합니다. 세이브를 이미 읽었다면 구단 이름·ID로 검색합니다. 목록이 없으면 **세이브 구단 읽기**를 누르거나 ID를 직접 입력할 수 있습니다.
2. 구단을 선택하고 **영입된 선수만 / 방출된 선수만 / 방출·영입 모두** 중 하나를 고른 뒤 **추가 · 방향 변경**을 누릅니다.
3. 다른 구단도 추가하고 각 방향을 따로 지정합니다. 선택한 구단을 다시 선택하면 방향을 수정하거나 삭제할 수 있습니다.
4. **범위 저장**을 누릅니다. 이 동작 자체로 Codex를 호출하지 않습니다.

| 구단 설정 | 이동 | 생성 여부 |
| --- | --- | --- |
| 맨유 · 영입만 | 아스날 → 맨유 | 생성 |
| 맨유 · 영입만 | 맨유 → 아스날 | 제외 |
| 맨유 · 방출만 | 맨유 → 아스날 | 아스날을 선택하지 않아도 생성 |
| 맨유 · 모두 | 맨유 → 아스날 또는 아스날 → 맨유 | 둘 다 생성 |

영입은 **새 구단**, 방출은 **이전 구단**으로 판단합니다. 결과 유니폼은 항상 새 소속팀을 사용합니다. 무소속이 되면 새 유니폼 작업을 만들지 않지만, 이후 새 구단에 들어갈 때 이전 구단을 이어 비교합니다. 여러 조건에 맞아도 한 번의 이동에는 작업을 하나만 만듭니다.

직접 설정의 **내가 맡은 구단도 함께 포함**은 목록 밖의 내 구단을 추가합니다. 목록에 직접 지정한 구단은 그 구단의 개별 방향이 우선합니다. 구단 목록은 ‘직접 설정’ 모드에서만 적용되며 다른 프리셋과 숨겨진 합집합을 만들지 않습니다.

### 리그 참가 구단

프리미어리그·세리에 A·라리가·리그앙·분데스리가 참가 구단은 **해당 세이브의 현재 시즌 일정**으로 읽습니다. 대회 DB ID(11/32/67/16/22)를 세이브 내부 대회 키와 연결해 참가 구단을 구합니다. 현실의 고정 구단 명단을 쓰지 않아 세이브에서 승격·강등된 구단이 반영됩니다. 7월을 시즌 경계로 사용합니다.

리그 프리셋을 저장한 후 세이브 구단 읽기 또는 감시를 시작하면 추가 리더를 실행합니다. 해당 일정이 아직 생성되지 않았거나 리더가 지원하지 않는 경우 화면에 안내합니다. 미확인 리그 구단을 국가 전체나 현실 명단으로 대신 포함하지 않습니다. 구단 직접 설정은 리그 일정 읽기에 의존하지 않습니다. 실제 사용자 세이브에서 리그 리더의 호환성은 추가 확인이 필요합니다.

### 추가 조건과 호출 상한

**생성 범위 → 범위 저장 아래 왼쪽의 고급설정** 버튼을 누르면 별도 팝업이 열립니다. 상단 탭에는 고급설정을 표시하지 않으며 시작 시에도 열지 않습니다. **창 닫기·X·Esc**로 닫고 같은 버튼으로 다시 열 수 있습니다. 닫았다 열어도 현재 편집 값은 유지하며, 파일에 반영하려면 **고급설정 저장**을 누르세요. **범위 저장**도 현재 편집한 전체 설정을 함께 저장합니다.

| 항목 | 기본값 |
| --- | --- |
| 추가·제외 선수 ID, 생성선수 매핑 ID | 빈칸 · 별도 지정 없음 |
| 최대 나이 | 전체 |
| 최근 24시간 호출 상한 | 제한 없음 |
| 같은 선수 재생성 간격 | 제한 없음 |
| 대기열 추가 후 생성 대기 | 대기 없음 |
| 감시 간격 | 세이브 업데이트 1회마다 |
| 처음 발견한 선수도 생성 | 끔 · 기준만 기록 |

제한 항목에 숫자를 입력하면 적용하며 0·빈칸은 제한 없음입니다. 기존 버전의 호출 상한 20회·재생성 24시간·생성 대기 30초가 모두 그대로인 설정은 새 기본값으로 전환합니다. 하나라도 별도로 조정한 묶음은 유지합니다. 이전 초 단위 감시 간격은 제거하고 저장 횟수 기본값 1회로 전환합니다.

- **추가 선수 ID**는 프리셋·구단 선택에 더해 적용하는 개별 대상입니다. **제외 선수 ID**는 모든 선택보다 우선합니다.
- 최대 나이 0은 전체 나이입니다. 나이를 읽지 못한 선수는 나이 제한이 있을 때 제외합니다.
- 생성선수 여부를 ID 크기로 추측하지 않습니다. 기존 XML의 r- 매핑과 별도 지정한 생성선수 ID를 사용합니다.
- 호출 상한은 최근 24시간의 Codex 실행 시도 수이며 실패·재시도도 포함합니다. 상한과 재생성 간격에 걸린 작업은 대기 후 자동 진행합니다.
- 최초 읽기는 기본적으로 기준만 만듭니다. 범위를 늘려도 과거 이적을 소급 생성하지 않습니다. 현재 선수도 생성하려면 **현재 범위도 생성 대기**를 선택할 수 있으며 영입/현재 소속 조건에 맞는 선수만 추가됩니다.
- 같은 선수가 다시 이동하면 이전 미완료 작업을 대체합니다. 합성 중 새 소속으로 바뀌면 그 결과는 적용하지 않습니다.
- 자료 점검과 완성 이미지의 디스크·XML 저장은 감시 중 자동 재시도합니다. 실제 AI 호출의 실패·중단·도구 사용 불가는 확인 후 수동 재시도합니다.

### 저장 횟수에 따른 생성 간격

**감시 간격 · 세이브 업데이트 횟수**에 1 이상의 정수를 입력합니다. 1이면 매 업데이트마다, 2이면 두 번째 업데이트마다 누적 생성 작업을 처리합니다. 이적은 각 업데이트에서 기록하므로 첫 번째 업데이트의 방출도 두 번째 업데이트까지 유지됩니다. 그 사이 같은 선수가 다시 이동했다면 최신 소속의 작업만 남깁니다. 횟수가 차면 여러 대기 작업을 다음 저장 없이 이어 처리합니다.

최초 기준 읽기와 같은 파일의 반복 점검은 횟수에서 제외합니다. 횟수는 작업 폴더에 보관해 재시작 후 이어 세며, 간격 값을 변경하면 횟수를 0부터 다시 셉니다. 소속·선수 정보 읽기 자체는 Codex를 호출하지 않습니다. 이미 합성한 이미지의 저장 복구도 이 간격과 관계없이 진행합니다.

횟수는 프로그램이 확인한 완료된 파일 갱신 기준입니다. 앱을 끈 동안 또는 한 번의 합성이 진행되는 동안 같은 파일에 여러 번 덮어쓴 저장은 다음 확인에서 한 번으로 합쳐질 수 있습니다. 파일이 작성 중일 때는 완료를 기다리며 내부 파일 확인 주기는 사용자 설정으로 노출하지 않습니다.

## 홈의 최근 생성 이미지

홈 오른쪽에는 가장 최근 생성한 350×350 페이스온과 선수·새 소속팀이 표시됩니다. 생성이 끝나면 자동으로 바뀌며 다시 실행해도 작업 기록에서 불러옵니다. 아래 통계에는 대기·생성 중·저장 완료 작업 수가 표시됩니다. 다른 작업 폴더를 선택하면 그 폴더의 기록과 결과를 사용합니다.

## 감지와 Codex 처리 방식

프로그램은 지정한 `.fm` 파일의 변경을 감시하고, 파일의 복사본을 읽습니다. 원본 세이브를 수정하지 않습니다. 매번 디스크 파일을 다시 파싱하지 않으며 변경 시에만 읽습니다. 다만 세이브를 읽을 때는 범위 밖 선수를 포함한 목록도 파싱하므로 큰 세이브에서는 메모리와 시간이 필요합니다.

소속은 기본적으로 세이브 리더의 등록 팀 구단(`club_uid`)으로 비교합니다. v0.4.2는 **등록 팀이 그대로인데 임대가 아닌 선수의 현재 계약 구단만 변경된 경우** 그 구단을 새 소속으로 사용하고 다음 저장에도 유지합니다. 등록 팀 자체가 바뀌면 등록 팀을 우선하며, 임대 중에는 계약 원소속 구단으로 유니폼을 바꾸지 않습니다. 계약 정보나 임대 여부가 불명확하면 임의로 계약 구단을 새 소속이라고 추측하지 않습니다.

새 버전의 최초 읽기에서는 등록 팀과 계약 구단이 다르다는 이유만으로 과거 이적을 만들지 않습니다. 기존 버전에서 계약 정보를 저장하지 않았던 경우도 첫 새 정보는 기준으로 보관합니다. 에디터 테스트는 **변경 전 저장을 읽은 뒤 → 에디터 이동 → 같은 파일 저장** 순서로 진행하세요. 과거 세이브로 돌아가는 테스트라면 새 작업 폴더가 필요합니다.

리더가 실제 게임의 임대·B팀·제휴 구단을 어떻게 해석하는지는 사용 중인 세이브와 대조 검증이 필요합니다. 두 저장 사이에 A → B → C로 이동했다면 마지막 C만 볼 수 있습니다. 자동저장이 여러 파일로 순환하면 지정한 파일이 갱신될 때 감지합니다.

### 신규 작업이 0개일 때

로그에서 다음 정보를 구분합니다. 지정한 선수 ID의 상세 정보는 최대 10명까지 표시합니다.

- 최초 기준 기록인지, 이전 저장과 비교한 결과인지
- 실제 소속 변화 수, 생성 범위에서 제외한 수, 추가한 작업 수
- 지정 선수의 이전 → 현재 소속, 등록 팀 구단 ID와 현재 계약 구단 ID
- 구단/선수 범위 밖, 제외 ID, 나이 제한, 무소속 등 생성 제외 사유
- 지정한 선수 ID를 세이브에서 찾지 못한 경우

예를 들어 맨유의 ‘영입된 선수만’을 선택한 상태에서 선수가 아스날로 나가면 범위 밖입니다. 맨유의 ‘방출된 선수만’ 또는 ‘방출·영입 모두’를 선택하면 아스날을 따로 선택하지 않아도 생성합니다.

최근 진단은 작업 폴더의 `latest_detection.json`에 자동 저장합니다. **작업 대기열 상단**의 **감지 진단 저장**으로 같은 JSON을 내보낼 수도 있습니다. 아직 진단이 없다면 먼저 **선수·이적 읽기**를 눌러 읽기가 끝날 때까지 기다리세요. 파일에는 감시 세이브 경로, 게임 날짜, 지정 선수 및 소속 변경 일부의 비교 정보가 포함됩니다. 전체 세이브를 내보내거나 Codex를 호출하지 않습니다.

작업별 폴더에 `original.png`, `kit.png`, `prompt.txt`, 결과 스키마를 준비하고 `codex exec`를 호출합니다. 이미지 도구를 사용할 수 없으면 보류합니다. 유료 API로 자동 전환하거나 별도 이미지 서비스를 자동 가입하지 않습니다. 계정의 실제 사용 한도·제공 기능은 사용 환경에 따라 확인해야 합니다.

Codex에는 원본 얼굴·유니폼 참조와 선수·구단 이름을 전달합니다. 전체 세이브는 프롬프트에 넣지 않습니다. 작업은 `workspace-write` 샌드박스에서 실행하며 승인 우회 플래그는 사용하지 않습니다. 비대화 실행의 승인 요청은 허용하지 않아 권한이 필요한 동작은 실패할 수 있습니다. 사용자의 Codex 설정·신뢰된 MCP 구성도 실제 동작에 영향을 줄 수 있습니다.

AI 원본은 350~4096px 정사각 PNG로 받고, 최종 결과는 **정확히 350×350 PNG**로 검증합니다. 로컬 이름 렌더링 기록도 확인합니다. 얼굴 동일성이나 유니폼 정확성을 자동 판정하지는 않습니다.

## 이름 폰트와 코너 모양

기본 폰트는 **koverwatch.ttf**입니다. 파일을 **프로그램 폴더의 config.json 옆**에 넣으세요. 기본 설치 예시는 `D:\FMFaceAutomator\koverwatch.ttf`입니다. 별도 위치의 설정 파일을 사용한다면 그 설정 파일 옆을 기준으로 합니다. EXE 실행 시에도 설정 파일 옆에 보관하세요. **폰트 파일은 저장소에 포함되어 있지 않습니다.**

**폴더 · 연결 → 이름 글꼴 → 폰트 불러오기**에서 다른 **TTF·OTF·TTC** 파일을 직접 선택할 수도 있습니다. **기본 글꼴**은 `koverwatch.ttf` 경로로 돌아갑니다. 변경 후 **설정 저장**을 누르세요. PC에 글꼴을 설치하지 않아도 파일을 직접 읽으며, 선택 파일은 해당 위치에 보관해야 합니다. TTC는 첫 번째 글꼴을 사용하며 이름 길이에 맞춰 글꼴 크기를 자동 조정합니다.

이전 버전의 미설정 또는 알려진 시스템 기본 폰트(맑은 고딕·Noto Sans CJK 등) 설정은 업데이트 시 `koverwatch.ttf`로 전환합니다. 다른 이름의 사용자 지정 파일은 유지합니다. 전환 후 직접 지정한 선택은 다음 실행에도 유지합니다. 시스템 폰트를 자동 검색하거나 대체하지 않습니다.

기본 파일이 없더라도 설정 저장·이적 읽기는 가능하지만 **합성은 Codex 호출 전에 보류**합니다. 파일을 넣으면 감시 중 자료 재점검에서 다시 진행합니다. 손상된 파일이나 직접 지정한 잘못된 경로는 설정 저장 또는 합성 전 검사에서 안내합니다. 실제 `koverwatch.ttf` 파일이 제공되지 않아 이번 테스트는 다른 실제 폰트를 렌더링 자료로 사용했으며 해당 폰트의 실제 모양 확인은 별도로 필요합니다.

최종 이미지는 네 모서리 모두 **60px 반경**이며 가장자리를 부드러운 투명도로 처리합니다. 폰트와 새 모서리는 이후 생성되는 결과부터 반영합니다. 기존 PNG나 저장 재시도용 완성 결과를 자동으로 다시 만들지는 않습니다.

## 페이스팩 적용과 복구

게임에서 사용하는 그래픽 폴더 안의 기존 페이스팩 또는 새 폴더를 **페이스팩 저장 폴더**로 선택하세요. **처음에도 비어 있을 필요가 없습니다.** 원본 얼굴 폴더와 같은 곳으로 지정할 수도 있습니다. 이전 작업 폴더에서 사용하던 출력 폴더도 재사용할 수 있습니다.

최종 PNG는 **선수ID.png**로 저장하고 같은 선수의 다음 결과는 해당 파일을 교체합니다. `config.xml`의 해당 선수 초상화 from도 동일한 ID로 갱신합니다. 기존 팩의 임의 파일명·하위 경로·다른 선수·키트 등 다른 매핑과 XML 속성은 보존합니다. 일반 ID는 `graphics/pictures/person/ID/portrait`, 지정된 생성선수는 `graphics/pictures/person/r-ID/portrait`로 매핑합니다. 이 규칙의 FM27 스킨별 동작은 실제 게임에서 확인해야 합니다.

**매 작업의 성공 조건은 PNG와 config.xml 저장이 모두 끝나는 것**입니다. 실패했거나 합성 중 다시 이적한 이미지는 매핑에 추가하지 않습니다. 기존 선수 매핑은 보존하고 동일 선수만 최신 파일로 바꿉니다. XML은 백업 후 임시 파일을 완성하여 교체합니다.

합성은 끝났지만 디스크·폴더 권한 때문에 매핑 저장이 실패하면 ‘저장 실패’ 상태에 이미지를 보관합니다. 감시 중에는 60초마다 새 Codex 호출 없이 저장만 재시도합니다. 즉시 다시 시도하려면 **저장 재시도**를 누르세요. 이때 **합성 재시도**와 혼동하지 마세요. 합성 도중 다시 이적한 결과는 자동 적용하지 않습니다.

XML을 바꾸기 전에 `backups/`에 원본 XML과 교체할 대상 ID 이미지, 복구 정보를 저장합니다. 기존 팩 전체의 이미지를 매 작업마다 복사하지는 않습니다. **적용 백업 복구**로 선택한 작업의 대상 선수 매핑·이미지를 복구하며, 그 뒤에 처리한 다른 선수는 유지합니다. 원래 다른 파일명의 사진에 연결되어 있었다면 그 연결로 되돌리고 해당 원본 사진은 건드리지 않습니다. XML 저장 실패 시 교체했던 ID 이미지도 원복하고 생성 결과는 재시도용으로 보관합니다.

저장 폴더의 다음 항목은 FM 표시용이 아닌 앱의 관리 자료입니다.

| 항목 | 역할 |
| --- | --- |
| `.fm-face-lock/` | 같은 페이스팩에 여러 작업이 동시에 PNG·XML을 쓰지 않도록 OS 잠금을 거는 위치. 작업이 끝나도 잠금 파일은 남지만 실제 잠금은 해제됩니다. |
| `backups/` | 변경 전 XML·대상 선수 이미지·복구 정보를 보관. 삭제하면 해당 변경 전 상태로 복구할 수 없습니다. |
| `.fm-face-shared` | 기존 파일 또는 다른 작업 폴더의 결과가 섞인 팩이라는 표시. 원본 이미지 검색에서 해당 팩을 제외하지 않고, 앱 전용 팩에만 허용하는 일괄 파일명 변환을 막는 데 씁니다. |

앱에서 계속 쓰는 폴더라면 위 항목을 유지하세요. 잠금 폴더나 공유 표시를 임의로 지우면 동시 저장 보호나 폴더 분류에 영향을 줄 수 있습니다. 이미지와 매핑의 게임 적용 자체는 선수 PNG와 `config.xml`이 담당합니다.

손상된 XML이나 DTD/엔티티, ID 이미지가 다른 대상 매핑에도 공유된 경우에는 파일을 임의로 덮어쓰지 않고 보류합니다. 같은 저장 폴더를 여러 작업 폴더가 사용할 때에는 폴더 잠금으로 동시 갱신을 막고 자동 저장 재시도로 이어갑니다.

v0.3.3 이하의 `ID_작업번호.png`는 감시 시작 시 재합성 없이 `ID.png`와 대응 XML로 변환합니다. 기존 파일은 `backups/legacy/`로 옮깁니다. 이전 버전의 XML만 있는 백업도 해당 파일을 사용해 복구할 수 있습니다. 다른 페이스팩에서 같은 ID를 매핑하는 충돌이나 게임의 로딩 순서까지 자동 해결하지는 않습니다. 게임 안에서 캐시나 그래픽을 다시 불러오는 동작이 필요할 수 있습니다.

세이브별로 다른 작업 폴더를 쓰세요. 페이스팩 저장 폴더는 재사용할 수 있으며 같은 ID는 마지막으로 저장한 결과가 됩니다. 다른 파일로 바꾸거나 이전 날짜 세이브로 되돌아가는 경우 새 작업 폴더가 필요합니다. 같은 파일명에 다른 커리어를 덮어쓰면 자동으로 완벽히 구분할 수 없습니다.

## 실제 게임 없이 감지 확인

`examples/before.json`을 별도의 `current.json`으로 복사하고 앱의 입력으로 지정합니다. 최초 읽기 뒤 `examples/after.json` 내용으로 **같은 current.json 파일**을 바꾼 다음 다시 읽으세요. Demo Player의 Club A → Club B 변경이 대기열에 1개 나타납니다. 원본 이미지와 Codex가 없으므로 합성 검증 예시는 아닙니다.

기존 JSON 형식이 아닌 임의 CSV·HTML 파일은 자동으로 해석하지 않습니다. 예시 JSON은 FM 세이브 어댑터와 같은 내부 형식입니다.

## 개발과 출처

```console
python -m unittest discover -s tests -v
python app.py --config config.json --scan
```

세이브 읽기는 [fmsave](https://github.com/rhiever/fmsave)의 공개 Python 라이브러리를 사용합니다(MIT, 0.12.6 고정). 라이브러리 문서상 FM27 `27.0.0+2486695`가 전체 리더 등록 대상이며, 0.12.6에는 `27.1.0+2505117`의 구단 레이아웃 수정이 포함되었습니다. 후자는 모든 리더가 등록된 빌드가 아니므로 `known_build`가 false일 수 있습니다. 이 앱은 필요한 선수·구단 읽기에 한해 해당 빌드를 명시적으로 허용하고 엄격 무결성 검사 실패는 중단합니다. 다른 미등록 빌드는 계속 거부합니다. 알려진 빌드 또는 호환 대상으로 지정됐다는 사실이 모든 필드의 게임 대조 검증을 의미하지는 않습니다.

Codex 연결은 [공식 비대화 실행 문서](https://developers.openai.com/codex/noninteractive/)와 설치된 CLI의 도움말을 기준으로 작성했습니다. 이미지 검증에는 Pillow를 사용합니다. 의존성 코드는 이 소스 압축에 복제하지 않고 설치 시 공식 패키지 저장소에서 받습니다.

커뮤니티가 만든 비공식 프로그램이며 Sports Interactive 또는 SEGA의 공식 제품이 아닙니다.
