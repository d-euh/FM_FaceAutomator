# FM Face Automator · v0.3.2 미리보기

FM Newgen Face Studio와 연결하지 않는 독립형 데스크톱 프로그램입니다. Windows 10용 실행 배치파일과 Python 소스를 제공합니다. 이 배포물에는 미리 빌드한 Windows EXE가 없습니다.

**이번 버전의 자동화 단위는 ‘세이브가 저장된 뒤 확인할 수 있는 이적’입니다.** 저장되지 않은 게임 메모리의 이적을 실시간으로 읽지는 않습니다. 실제 FM27 세이브, Windows 10, 사용자 계정의 Codex 이미지 도구로 끝까지 실행한 검증은 아직 하지 못했습니다.

v0.2에서는 **공통·선수별 추가 지시**, **350×350 건조폼과 하단 선수 이름**, **작업마다 PNG와 FM config.xml 자동 저장**을 제공합니다. 기존 `auto_apply` 옵션은 제거했으며 이전 설정에 false가 남아 있어도 저장은 자동 진행합니다. 앱 환경 설정은 `config.json`, FM 이미지 매핑 파일은 `config.xml`로 서로 다릅니다.

v0.3은 **자료 폴더 자동 검색**, **기존 페이스팩·2D 키트의 config.xml 읽기**, **home/away/third 키트 선택**을 추가했습니다. 자동으로 위치를 알아낼 수 없는 폴더는 직접 경로를 입력하거나 폴더 선택 버튼으로 지정할 수 있습니다.

v0.3.2는 세이브 리더를 0.12.6으로 올리고 **FM27 `27.1.0+2505117`**을 호환 대상으로 추가했습니다. 이 빌드가 ‘검증 대상 외 게임 빌드’로 차단되던 문제를 수정했으며 선수·구단 읽기의 엄격 검사는 유지합니다. 앱을 닫고 PowerShell에서 `git pull --ff-only` 후 `setup_windows.bat`를 다시 실행하고 시작하세요.

## 실행

1. [python.org](https://www.python.org/downloads/windows/)에서 Python 3.12 이상을 설치합니다. Tk와 Python Launcher를 포함하세요.
2. 압축을 풀고 `setup_windows.bat`를 실행합니다. 전용 `.venv`에 세이브 읽기 및 이미지 검증 라이브러리를 설치합니다.
3. [Codex CLI](https://developers.openai.com/codex/cli/)를 설치하고 해당 PC에서 로그인을 완료합니다. 사용 계정과 CLI 환경에서 이미지 생성 도구를 사용할 수 있어야 합니다.
4. `start_windows.bat`를 실행합니다. 최초 실행 시 `config.json`이 만들어집니다.
5. 세이브 파일과 작업 폴더를 선택합니다. **자료 폴더 자동 찾기**에서 기존 페이스팩·키트 폴더를 검색하거나, 각 경로 칸에 직접 입력합니다. 출력은 별도의 비어 있는 전용 페이스팩 폴더를 선택하세요.
6. ‘Codex 찾기’로 실제 `codex.exe`를 지정합니다. Windows의 `codex.cmd`나 `codex.bat`는 실행 대상으로 받지 않습니다.

`build_windows.bat`는 Windows에서 EXE 묶음을 만드는 선택 기능입니다. PyInstaller를 설치하고 `dist\FMFaceAutomator\`에 생성합니다. 빌드 스크립트는 이 Linux 환경에서 실행 검증하지 않았습니다. 배포할 때는 EXE 하나가 아닌 생성된 폴더 전체를 사용하세요.

## 첫 사용

1. ‘작업 대기열 · 미리보기’에서 **선수·이적 읽기**를 누릅니다. 첫 읽기는 기준점만 저장하며 Codex를 호출하지 않습니다.
2. **선수 ID 목록 저장**으로 CSV를 만듭니다. CSV의 선수 ID와 구단 ID는 게임의 데이터베이스 ID입니다. 세이브 내부 `uid`와 혼동하지 마세요.
3. 기존 팩 폴더를 지정하면 그 안의 `config.xml`에서 선수·구단 ID와 실제 이미지 파일을 연결합니다. 매핑이 없는 자료는 아래 파일명 규칙을 사용할 수 있습니다.

```text
portraits/
  900001.png          # 선수 고유 ID, 동일성을 유지할 원본 얼굴
kits/
  20.png              # 새 소속 구단 고유 ID, 유니폼 참조 사진
  20_away.png         # 원정 키트를 별도로 준비하는 경우
```

4. 설정에서 생성 범위를 정합니다. 기본값은 ‘내가 맡은 구단 포함’, 24시간 호출 상한 20회, 재생성 간격 24시간, 변경 대기 30초입니다.
5. 현재 선수들에게도 처음부터 합성을 적용하려면 **현재 범위도 생성 대기**를 누릅니다. 이후 새로 나타나는 선수까지 자동으로 대기에 넣으려면 ‘처음 발견한 선수도 생성’을 켭니다.
6. **감시·생성 시작**을 누릅니다. 이때부터 조건에 맞는 작업을 하나씩 Codex에 전달합니다. 계정 사용량이 발생할 수 있습니다.
7. 합성이 성공하면 프로그램이 건조폼을 입히고, 하단에 이름을 넣고, 350×350 PNG와 `config.xml`을 저장합니다. 둘 다 저장되어야 ‘완료’가 됩니다. **이미지 미리보기**에서 얼굴 동일성과 유니폼을 확인할 수 있습니다.

## 얼굴·유니폼 폴더 자동 검색과 직접 지정

설정 화면의 **자료 폴더 자동 찾기**를 누릅니다. 다음 위치 중 실제 존재하는 폴더를 검색합니다.

- Windows에서 문서 폴더로 등록된 위치(리디렉션된 문서 폴더 포함)
- 문서 및 OneDrive 아래의 `Sports Interactive\Football Manager 27\graphics` 또는 `Football Manager 2027\graphics`
- 선택한 세이브가 `games` 폴더 안에 있으면 그 옆의 `graphics` 폴더
- 현재 입력된 원본 얼굴·키트 폴더, 사용자가 ‘추가 검색 위치’로 지정한 폴더

드라이브 전체나 사용자 홈 전체를 자동 검색하지는 않습니다. 다른 드라이브에 자료를 옮겼다면 ‘추가 검색 위치’를 지정해 검색하거나, 설정의 원본 얼굴·키트 경로를 직접 입력하세요. 경로 입력과 폴더 선택은 자동 검색 없이도 사용할 수 있습니다.

검색 결과에는 폴더별로 얼굴 매핑 수·키트 매핑 수와 검색 근거가 표시됩니다. 얼굴 또는 키트 후보가 하나로 좁혀지면 **‘이 경로가 맞나요?’**를 각각 표시합니다. **예**를 누르면 해당 경로를 사용하고, **아니요**를 누르면 바로 폴더 선택 창이 열립니다. **취소** 또는 폴더 선택 창에서 취소하면 해당 항목의 기존 경로를 유지합니다.

후보가 여러 개면 필요한 행을 선택하여 **얼굴 경로 확인**, **키트 경로 확인**을 누릅니다. 이때도 같은 확인 절차를 거칩니다. 확인을 마친 뒤 검색 창을 닫고 설정을 저장합니다. 한 폴더에 두 종류가 함께 있어도 각각 확인합니다. 파일명만 숫자인 폴더는 얼굴/키트 종류를 자동으로 단정하지 않고 사용자가 용도를 선택하도록 표시합니다.

기존 매핑에서 인식하는 형태는 다음과 같습니다. XML의 `from` 값을 파일명으로 사용하므로 사진 파일명이 선수 ID나 구단 ID일 필요는 없습니다.

```xml
<record from="photos/player_photo" to="graphics/pictures/person/900001/portrait"/>
<record from="photos/newgen_photo" to="graphics/pictures/person/r-900002/portrait"/>
<record from="manchester_h" to="graphics/pictures/team/20/kits/home"/>
```

유니폼 유형은 설정의 **home / away / third**에서 고릅니다. 3D `kit_textures` 매핑은 2D 유니폼 참조와 구분하여 검색 결과에서 제외합니다. 2D 이미지나 실제 유니폼 사진을 참조로 사용할 수 있지만, 로고만 있는 폴더나 게임 기본 압축 리소스를 자동으로 유니폼 사진으로 바꾸지는 않습니다.

지원 이미지 형식은 PNG, JPG/JPEG, WebP, BMP입니다. 선택한 두 이미지만 PNG로 변환하여 Codex 작업 폴더에 복사합니다. 원본 팩의 이미지와 XML은 수정하지 않습니다. 출력 페이스팩과 작업 폴더는 원본 검색에서 제외합니다.

동일한 ID에 서로 다른 파일이 여러 개 연결되면 임의로 하나를 선택하지 않습니다. 사용할 팩의 더 작은 하위 폴더를 지정하세요. XML이 가리키는 파일이 없으면 해당 작업은 보류하며, 임의의 동명 이미지로 대체하지 않습니다. 인덱스는 실행 중 캐시하며 파일을 못 찾으면 한 번 새로 읽고, 그 외에는 최대 60초 단위로 갱신합니다.

기존 XML에 일반 ID 매핑이 없고 `r-ID` 매핑이 있으면 그 근거를 사용해 생성선수 대상 경로를 유지합니다. XML이 없는 자료에서 `r-`가 필요한 경우에는 기존 ‘생성선수 r- 매핑 ID’ 설정을 사용할 수 있습니다. ID 크기만으로 생성선수 여부를 추측하지 않습니다.

## 추가 지시와 건조폼

‘추가 지시 · 건조폼’ 탭의 공통 지시는 모든 다음 합성에 적용합니다. 예: `비 오는 경기장에서 골을 넣고 활짝 웃으며 오른손을 든 모습. 앞머리는 뒤로 넘겨주세요.`

대기열의 선수를 선택하고 **선수별 이름·지시**를 누르면 하단 표시 이름과 그 선수의 추가 지시를 따로 저장할 수 있습니다. 공통 지시와 선수별 지시는 함께 전달하며, 충돌하면 선수별 지시를 우선합니다. 해당 ID가 다른 인물에게 재사용된 경우 이전 인물의 지시는 적용하지 않습니다. 변경은 다음 합성부터 반영되며 이미 저장된 이미지를 자동으로 다시 합성하지는 않습니다.

- 유효한 추가 지시가 없으면 원본 머리카락·표정·자세를 유지하라는 문구를 넣습니다.
- 공통 또는 선수별 추가 지시가 하나라도 있으면 위 유지 문구를 넣지 않습니다. 기본 사진 스타일보다 사용자 추가 지시를 우선합니다.
- 선수 얼굴 동일성은 기본으로 유지하도록 요청합니다.
- Codex는 글자나 테두리 없는 인물 원본 `portrait.png`를 생성합니다. 프로그램이 로컬에서 최종 **350×350**으로 맞추고 하단에 정확한 이름을 그립니다. AI에게 선수 이름 철자를 그리도록 맡기지 않습니다.
- 기본 폼은 둥근 모서리·하단 어두운 그라데이션·가운데 정렬 이름을 가진 건조형 카드입니다. 참고 프로그램의 원본 템플릿 자산을 복제한 것은 아닙니다. 이름은 영문 대문자로 표시하며 한글·악센트 문자도 지원합니다. 긴 이름은 글꼴을 줄이거나 두 줄로 배치하며, 그래도 맞지 않으면 표시 이름 수정을 안내합니다.
- 정확한 별도 폼이 있으면 **투명도를 포함한 350×350 PNG 템플릿**을 선택할 수 있습니다. 이름은 템플릿 위에 그립니다. 템플릿에는 이름이 미리 그려져 있지 않은 것이 적합합니다.
- 이름 글꼴은 Windows 맑은 고딕을 우선 사용하며 TTF/OTF/TTC 파일을 별도로 선택할 수도 있습니다. 선택한 글꼴이 필요한 문자를 지원해야 합니다.

작업 폴더의 `prompt.txt`와 `request.json`에 실제 적용한 지시와 표시 이름이 남습니다. 이미지 도구 호출 전에 이름·글꼴·템플릿과 전용 페이스팩 폴더를 확인합니다.

## 생성 범위와 호출량

- 내 구단, 추가 구단 ID, 추가 선수 ID는 **합집합**입니다. 추가 선수 선택이 내 구단으로 제한되지는 않습니다.
- 제외 선수 ID와 최대 나이는 선택 범위에 추가로 적용됩니다. 최대 나이 0은 전체 나이입니다. 나이를 읽지 못한 선수는 나이 제한이 있을 때 제외합니다.
- ‘모든 구단 포함’은 모든 소속 구단을 대상으로 합니다. 무소속 선수에게는 새 유니폼 작업을 만들지 않습니다.
- 범위 밖 선수도 소속 변경을 비교하기 위한 최소 기준 데이터는 로컬에 보관합니다. 범위는 **AI 생성 대상**을 제한합니다.
- 생성선수 여부를 ID 크기로 추측하지 않습니다. 기존 XML의 `r-` 매핑을 읽으며, 별도 지정이 필요하면 ‘생성선수 r- 매핑 ID’에 입력하세요. 이 항목은 생성 범위 자체를 추가하지 않습니다.
- 호출 상한은 자정 기준이 아닌 **최근 24시간의 Codex 실행 시도 수**입니다. 실패와 재시도도 계산합니다. 금액·토큰 예산의 상한은 아닙니다.
- 같은 선수가 변경 대기 시간 안에 여러 번 이동하면 이전 미완료 작업을 대체합니다. 합성이 시작된 뒤 다시 이적하면 해당 결과의 적용을 막습니다. 이미 발생한 사용량을 취소할 수는 없습니다.
- 같은 선수의 최근 Codex 실행 뒤 재생성 간격이 지나기 전에는 새로운 작업을 기다리게 합니다. 사용자가 실패한 동일 작업을 재시도하는 경우에는 호출 상한을 적용합니다.
- 범위를 늘려도 과거 이적을 전부 소급 생성하지 않습니다. ‘현재 범위도 생성 대기’로 현재 선수들을 추가할 수 있습니다.
- 실패·중단·이미지 도구 사용 불가·참조 이미지 누락은 자동 무한 재시도하지 않습니다. 원인을 수정한 뒤 작업을 선택하여 재시도하세요.

## 감지와 Codex 처리 방식

프로그램은 지정한 `.fm` 파일의 변경을 감시하고, 파일의 복사본을 읽습니다. 원본 세이브를 수정하지 않습니다. 매번 디스크 파일을 다시 파싱하지 않으며 변경 시에만 읽습니다. 다만 세이브를 읽을 때는 범위 밖 선수를 포함한 목록도 파싱하므로 큰 세이브에서는 메모리와 시간이 필요합니다.

소속은 세이브 리더의 ‘등록 팀 기준 club_uid’로 비교합니다. 임대의 원소속 구단 ID를 유니폼 대상으로 사용하지 않습니다. 리더가 실제 게임의 임대·B팀·제휴 구단을 어떻게 해석하는지는 사용 중인 세이브와 대조 검증이 필요합니다. 두 저장 사이에 A → B → C로 이동했다면 마지막 C만 볼 수 있습니다. 자동저장이 여러 파일로 순환하면 지정한 파일이 갱신될 때 감지합니다.

작업별 폴더에 `original.png`, `kit.png`, `prompt.txt`, 결과 스키마를 준비하고 `codex exec`를 호출합니다. 이미지 도구를 사용할 수 없으면 보류합니다. 유료 API로 자동 전환하거나 별도 이미지 서비스를 자동 가입하지 않습니다. 계정의 실제 사용 한도·제공 기능은 사용 환경에 따라 확인해야 합니다.

Codex에는 원본 얼굴·유니폼 참조와 선수·구단 이름을 전달합니다. 전체 세이브는 프롬프트에 넣지 않습니다. 작업은 `workspace-write` 샌드박스에서 실행하며 승인 우회 플래그는 사용하지 않습니다. 비대화 실행의 승인 요청은 허용하지 않아 권한이 필요한 동작은 실패할 수 있습니다. 사용자의 Codex 설정·신뢰된 MCP 구성도 실제 동작에 영향을 줄 수 있습니다.

AI 원본은 350~4096px 정사각 PNG로 받고, 최종 결과는 **정확히 350×350 PNG**로 검증합니다. 로컬 이름 렌더링 기록도 확인합니다. 얼굴 동일성이나 유니폼 정확성을 자동 판정하지는 않습니다.

## 페이스팩 적용과 복구

게임의 그래픽 폴더 안에서 **비어 있는 전용 하위 폴더**를 선택하세요. 기존 페이스팩 폴더 자체를 지정하면 적용을 거부합니다. 예: 게임에서 사용하는 graphics 폴더 아래 `FMFaceAutomator`.

프로그램은 새 파일 이름으로 PNG를 추가하고 자체 `config.xml`을 갱신합니다. 일반 ID는 `graphics/pictures/person/ID/portrait`, 지정된 생성선수는 `graphics/pictures/person/r-ID/portrait`로 매핑합니다. 이 규칙의 FM27 스킨별 동작은 실제 게임에서 확인해야 합니다.

**매 작업의 성공 조건은 PNG와 config.xml 저장이 모두 끝나는 것**입니다. 실패했거나 합성 중 다시 이적한 이미지는 매핑에 추가하지 않습니다. 기존 선수 매핑은 보존하고 동일 선수만 최신 파일로 바꿉니다. XML은 백업 후 임시 파일을 완성하여 교체합니다.

합성은 끝났지만 디스크·폴더 권한 때문에 매핑 저장이 실패하면 ‘저장 실패’ 상태에 이미지를 보관합니다. 문제를 수정하고 **저장 재시도**를 누르면 새 Codex 호출 없이 PNG와 XML 저장을 다시 시도합니다. 이때 **합성 재시도**와 혼동하지 마세요. 합성 도중 다시 이적한 결과는 자동 적용하지 않습니다.

설정 파일을 바꾸기 전에 `backups/`에 이전 매핑을 저장합니다. **적용 백업 복구**에서 백업을 선택하면 이전 매핑으로 되돌립니다. PNG와 작업 기록을 지우지는 않습니다. 다른 페이스팩에서 같은 ID를 매핑하는 충돌이나 게임의 로딩 순서까지 자동 해결하지는 않습니다. 게임 안에서 캐시나 그래픽을 다시 불러오는 동작이 필요할 수 있습니다.

세이브별로 다른 작업 폴더와 전용 페이스팩 폴더를 쓰세요. 다른 파일로 바꾸거나 이전 날짜 세이브로 되돌아가는 경우 새 작업 폴더가 필요합니다. 같은 파일명에 다른 커리어를 덮어쓰면 자동으로 완벽히 구분할 수 없습니다.

## 실제 게임 없이 감지 확인

`examples/before.json`을 별도의 `current.json`으로 복사하고 앱의 입력으로 지정합니다. 최초 읽기 뒤 `examples/after.json` 내용으로 **같은 current.json 파일**을 바꾼 다음 다시 읽으세요. Demo Player의 Club A → Club B 변경이 대기열에 1개 나타납니다. 원본 이미지와 Codex가 없으므로 합성 검증 예시는 아닙니다.

기존 JSON 형식이 아닌 임의 CSV·HTML 파일은 자동으로 해석하지 않습니다. 예시 JSON은 FM 세이브 어댑터와 같은 내부 형식입니다.

## 개발과 출처

```console
python -m unittest discover -s tests -v
python app.py --config config.json --scan
```

세이브 읽기는 [fmsave](https://github.com/rhiever/fmsave)의 공개 Python 라이브러리를 사용합니다(MIT, 0.12.6 고정). 라이브러리 문서상 FM27 `27.0.0+2486695`가 전체 리더 등록 대상이며, 0.12.6에는 `27.1.0+2505117`의 구단 레이아웃 수정이 포함되었습니다. 후자는 모든 리더가 등록된 빌드가 아니므로 `known_build`가 false일 수 있습니다. 이 앱은 필요한 선수·구단 읽기에 한해 해당 빌드를 명시적으로 허용하고 엄격 무결성 검사 실패는 중단합니다. 다른 미등록 빌드는 계속 거부합니다. 알려진 빌드 또는 호환 대상으로 지정됐다는 사실이 모든 필드의 게임 대조 검증을 의미하지는 않습니다.

Codex 연결은 [공식 비대화 실행 문서](https://developers.openai.com/codex/noninteractive/)와 설치된 CLI의 도움말을 기준으로 작성했습니다. 이미지 검증에는 Pillow를 사용합니다. 의존성 코드는 이 소스 압축에 복제하지 않고 설치 시 공식 패키지 저장소에서 받습니다.

커뮤니티가 만든 비공식 프로그램이며 Sports Interactive 또는 SEGA의 공식 제품이 아닙니다.
